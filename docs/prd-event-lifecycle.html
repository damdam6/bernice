01배경 & 문제 정의

2026-07 팀이 측정 종목을 실제로 개편했다 — 기존 4종목에서 45도패스캐치를 종료하고 패스 3종(체스트·바운드·원핸드)과 볼 캐치를 추가해 7종목이 됐다. 그런데 현재 사이트 구조는 종목 변동을 지원하지 않는다:

#문제결과
1파서(mapHeaderToEvents)가 목표 탭 전체 종목 ↔ 모든 회차 탭 헤더의 완전일치를 강제한다 — 목표에 종목을 추가하는 순간, 그 컬럼이 없는 과거 회차 탭 전부가 "종목 컬럼 없음" 에러/api/records가 500으로 실패해 홈·랭킹·프로필 사이트 전면 에러. 실시트가 이미 개편된 지금, 실제로 이 상태다
2종목을 없앨 합법적 방법이 없다 — 목표 탭 행 삭제는 금지(회차 헤더가 행 위치 참조)이고, 소프트 종료 개념도 없다운영자가 기존 행을 제자리에서 다른 종목으로 교체(45도패스캐치 → 패스 - 체스트)했고, 참조 수식 탓에 과거 회차의 45도패스캐치 기록이 패스 - 체스트라는 다른 종목 이름·다른 목표 기준으로 노출되는 의미 왜곡 발생
3회차 탭 생성(create-sheet)이 목표 탭 전체 종목으로 헤더를 만든다종료 개념이 생겨도 신규 회차에 종료 종목이 계속 포함된다 — 제외 규칙 필요

목표: 종목의 추가·종료를 시트 스키마와 사이트가 정식으로 지원한다. 과거 회차 데이터는 그 당시 측정한 종목 그대로 보존·표시되고, 종목이 바뀌어도 과거 회차 탭은 손댈 필요가 없으며, 사이트는 깨지지 않는다.

포지셔닝: 이 문서는 시트 연동 확정안의 목표 탭 스키마와 도메인 타입·API 계약을 개정하는 확장 PRD다. 명단의 탈퇴가 "행 삭제 대신 상태 변경"인 것과 동형으로, 종목의 종료도 "행 삭제 대신 종료 회차 기입"으로 다룬다.

02요구사항 — 사용자 확정 3건 (2026-07-24)

#요구이 문서의 해석·구체화
R1 종목은 중간에 사라질 수 있다. 따라서 종목 시트에 종료 회차를 넣는다 목표 탭에 종료 회차 열(E열)을 신설한다. 값은 회차 탭 이름과 같은 YYYY-MM-DD. 빈칸이면 현역 종목이다 (§04)
R2 종료 회차가 기입되어 있으면 해당 회차까지만 데이터가 존재함. 그 다음부터는 없다 경계 포함 — 종료 회차로 지정된 회차 까지는 그 종목의 기록이 존재할 수 있고, 그 이후 회차에는 존재하지 않는다. 이후 회차 탭에 그 종목 컬럼이 나타나면 데이터 모순으로 보고 fail-loud 에러로 알린다 (§05 V4)
R3 종목은 추가될 수 있다 목표 탭 맨 아래 행 추가만으로 종목을 추가한다. 추가 이후 생성되는 회차부터 자동 포함되고, 과거 회차 탭은 수정하지 않는다 — 컬럼이 없는 회차는 "그 회차 미측정"으로 처리한다 (§05 V3, 완전일치 강제의 완화)

03확정 결정 요약

#항목결정
D1종료 회차 표기회차 탭 이름과 동일한 YYYY-MM-DD 날짜. 경계 포함(그 회차까지 측정). 빈칸(또는 -) = 현역 — 만점 열의 null 표기와 동일 관례
D2시작 회차 열은 두지 않음어느 회차에서 어떤 종목을 측정했는지의 정본은 각 회차 탭 헤더다(컬럼이 있으면 측정). 종료 회차는 ① 이후 등장 금지의 상한 마커 ② 신규 탭 생성 제외 기준 ③ UI '종료' 표기, 세 용도만 담당한다. 중간에 건너뛴 회차(측정 생략)도 자연스럽게 허용된다
D3회차별 종목 스냅샷SessionEntry.scores의 "전 종목 key 항상 존재" 완전성 계약을 "그 회차 측정 종목 key만 존재"로 개정하고, 회차별 측정 종목 목록 Session.eventKeys를 계약에 신설한다 (§06)
D4fail-loud 유지완화는 "목표에 있는데 회차 헤더에 없음" 한 가지뿐. 목표에 없는 헤더·중복 헤더·빈 헤더 셀·종료 회차 이후 등장 컬럼·실존하지 않는 종료 회차 날짜는 전부 즉시 에러 (§05)
D5목표 탭 행 규칙 유지여전히 추가만(삭제·재배치 금지 — 회차 헤더가 행 위치를 참조). 종목 종료 = 행 삭제가 아니라 종료 회차 기입. 명단의 소프트 탈퇴와 동형
D6집계·화면 기준랭킹·홈 달성률·기록 입력은 그 회차의 측정 종목 기준. 개인 프로필의 추이·PB는 전체 종목(종료 포함)의 이력을 보존·표시 (§07·§08)
D7목표치는 단일 현재값 유지목표·만점·방향의 시점별 이력은 만들지 않는다. 종목의 의미(기준)가 바뀌는 개편은 이름 바꿔치기가 아니라 "기존 종목 종료 + 새 종목 추가"로 처리한다 — 45도패스캐치 → 패스 3종이 정확히 이 절차의 사례
D8종목 재개종료했던 종목을 다시 측정하려면 같은 행의 종료 회차를 비운다(현역 복귀 — 추이가 이어짐). 공백기 회차는 D2에 따라 자연스럽게 "미측정"으로 남는다. 명단의 탈퇴 → 활동 복귀와 동형

04시트 스키마 개정 — 목표 탭 '종료 회차' 열

목표 탭 헤더를 4열에서 5열로 개정한다. E열이 신설되는 것 외에 기존 열의 의미·순서는 그대로다.

항목규칙
헤더(1행)종목 | 목표 | 만점 | 방향 | 종료 회차 5열 엄격 일치. 4열 구 헤더는 신규 코드에서 에러 — 마이그레이션(§10)에서 시트를 먼저 고치므로 과도기 허용 규칙은 두지 않는다
종료 회차 값 형식빈칸 또는 - = 현역. 그 외에는 YYYY-MM-DD + 캘린더 유효 날짜여야 하며(회차 탭 이름 규칙 isValidRoundTabName 재사용), 형식이 어긋나면 목표 탭 파싱 에러(행 번호·종목명 포함)
실존 회차 검증종료 회차 날짜는 실존하는 회차 탭 이름과 일치해야 한다. 대조는 회차 탭 목록을 아는 조립 단계(build-records-response)가 수행 — 없는 날짜면 에러. 오타로 조용히 "영원히 현역"이 되거나 "전 회차 데이터 모순"이 되는 것을 막는다
측정 이력 없는 종목의 종료추가만 해두고 한 번도 측정하지 않은 종목을 접을 때도 행 삭제는 금지 — 종료 회차에 아무 과거 회차 날짜(예: 직전 회차)를 기입한다. "그 회차까지 데이터 존재 가능"이지 "존재 필수"가 아니므로 모순이 없다
기존 참조 안전성회차 탭 헤더 수식은 ='목표'!A행으로 A열만 참조하므로 E열 신설은 기존 회차 탭에 영향 없음. 편집 규칙의 행 순서 고정·추가만 규칙은 그대로 유효

05종목 생애주기 규칙 (판정·검증)

정의

  • 현역 종목 — 종료 회차가 빈칸. 신규 회차 탭 생성 시 헤더에 포함된다.
  • 종료 종목 — 종료 회차 기입. 그 날짜 회차 까지(경계 포함) 측정 데이터가 존재할 수 있고, 이후 회차에는 존재하지 않는다. 신규 회차 탭 생성에서 제외된다.
  • 회차 s에서 종목 e를 측정했다 ⇔ s 회차 탭 헤더에 e 컬럼이 존재한다 (D2 — 헤더가 정본).

생애주기 흐름

[추가] 목표 탭 맨 아래 행 추가 (종료 회차 빈칸) │ 과거 회차 탭 무수정 — 컬럼 없는 회차는 자동으로 "미측정" ▼ [현역] 이후 생성되는 회차 탭 헤더에 자동 포함 · 랭킹/게이지/입력 대상 │ 특정 회차에서 측정을 생략해도 됨(그 회차 탭에만 컬럼 없음) ▼ [종료] 마지막 측정 회차의 날짜를 종료 회차에 기입 │ 이후 신규 탭에서 제외 · 과거 기록·추이·PB는 그대로 보존 ▼ [재개] (선택) 종료 회차를 비우면 현역 복귀 — 같은 행 유지, 추이가 이어짐

검증 매트릭스 — 파서·조립이 던지는 에러

기존 fail-loud 철학(잘못 매칭된 점수가 섞이는 것보다 시끄러운 에러가 안전)을 유지한다. 완화되는 것은 V3 한 줄뿐이다.

#상황판정비고
V1회차 탭 헤더에 목표 탭에 없는 종목이 있음에러 (기존 유지)오타·참조 수식 파손 감지
V2회차 탭 헤더에 중복 종목 · 빈 헤더 셀에러 (기존 유지)
V3목표 탭 종목이 회차 탭 헤더에 없음정상 — "그 회차 미측정" (기존 에러에서 완화)이 문서의 핵심 변경. 종목 추가 시 과거 회차, 종료 종목의 이후 회차, 측정 생략 회차가 전부 이 규칙 하나로 수용된다
V4종료 회차 < 회차 날짜인데 그 회차 헤더에 종료 종목 컬럼이 존재에러 (신규)R2의 "그 다음부터는 없다" 위반 = 데이터 모순. 해결: 종료 회차를 그 회차 날짜로 올리거나, 잘못 만들어진 컬럼을 제거
V5종료 회차 값이 날짜 형식이 아니거나 캘린더에 없는 날짜에러 (신규 · 목표 탭 파싱)행 번호·종목명 포함 메시지
V6종료 회차 날짜가 실존 회차 탭에 없음에러 (신규 · 조립 단계)오타 방지 — §04 참고
경계 케이스 — 종료 회차 = 그 컬럼이 있는 마지막 회차: V4는 "종료 회차 초과 회차에 컬럼 존재"만 잡는다. 종료 회차로 지정된 회차 자체에 컬럼이 있는 것(정상 — 마지막 측정), 컬럼이 없는 것(측정 생략 후 종료) 모두 허용된다.

participated(회차 참여 여부) 파생은 공식 그대로 — "전 종목 unmeasured면 미참여"에서 '전 종목'의 분모가 그 회차 측정 종목으로 좁혀질 뿐이다.

06도메인 타입·API 계약 변경

shared/domain.ts + 도메인 타입·API 계약 + 프론트 런타임 검증(src/lib/parse-records-response.ts)을 함께 개정한다. FE·BE가 한 레포·한 배포로 나가므로 하위 호환 계약은 두지 않는다(빅뱅 교체).

타입변경의미
EventDefinition endSessionDate: string | null 신설 종료 회차(YYYY-MM-DD) — null이면 현역. events[]는 종료 종목을 포함한 전체를 목표 탭 행 순서대로 담는다(과거 회차 랭킹·추이가 종료 종목 정의를 필요로 함). '종료 여부'는 프론트가 endSessionDate !== null로 파생
Session eventKeys: string[] 신설 그 회차 탭 헤더의 측정 종목 key 목록(헤더 순서). 참가자가 0명인 회차에서도 측정 종목을 알 수 있도록 entries에서 유추하지 않고 명시한다

08화면 동작 변경

🏆 랭킹

  • 종목 칩 = 선택 회차의 측정 종목만(eventKeys 순서). 회차를 전환해 선택 중인 종목이 새 회차에 없으면 첫 종목으로 폴백한다. 미측정 종목×회차 조합의 막다른 빈 화면을 만들지 않는 것이 목적
  • 보충 행(미측정·면제·이상값 하단 배치, buildRankingRows)은 그 회차 측정 종목에 대해서만 존재 — scores[eventKey] 인덱싱이 §06 계약상 항상 유효해 별도 가드 불필요. 단 구현 시 undefined 방어는 유지
  • 7종목 칩은 기존 가로 스크롤 UI로 수용(디자인 변경 없음)

🏠 홈

  • 종목별 달성률 게이지 = 최신 회차 측정 종목만 (§06 achievementRates 자동 반영). 종료 종목은 최신 회차에 나타나지 않으므로 게이지에서 자연 소멸
  • 신규 빈 회차의 "참여 0명 · 0%" 노출 방식은 이 PRD의 비스코프(§12) — 기존 동작 유지

👤 개인 프로필

  • 레이더 축 = 선택 회차의 측정 종목 — 회차에 따라 4각형↔7각형으로 가변. radar-math는 이미 N축 일반이므로 7축 시각 검증만 필요
  • 성장 카드: 현역 종목은 전부 노출(기존과 동일). 종료 종목은 그 선수의 유효 기록이 1건 이상일 때만 노출하고 카드에 종료 뱃지를 단다 — 기록이 있는 선수에겐 이력이 보존되고, 없는 선수의 화면에 죽은 카드가 쌓이지 않는다
  • 추이 차트는 기존 희소 구조 그대로 — X축은 전체 회차, 점은 측정·기록 회차만. 종료 종목의 차트는 종료 회차 이후 구간에 점이 없을 뿐 별도 처리 없음
  • PB는 스파스 규칙 유지 — 종료 종목의 PB도 기록이 있으면 그대로 표시

🔒 관리자 — 기록 입력 플로우

  • 선수별 입력 필드 = 그 회차 eventKeys만 렌더 (현행은 전역 events[] 전체를 렌더 — 과거 회차에서 없는 종목 필드가 노출되는 버그가 됨)
  • 미입력/일부/완료 뱃지와 "완료 n/N" 판정 분모 = 그 회차 eventKeys (deriveEntryStatus·countCompleted 개정). 전역 종목 수를 분모로 두면 종목이 추가될 때마다 과거 회차의 '완료'가 '일부'로 롤백되는 오류가 생긴다

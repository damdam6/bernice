종목 ID와 표시 이름 분리

#177 코드 계약 · #178 운영 이전 인계 · 2026-09-29

이 문서가 기존 문서의 종목명=key, eventKeys, 목표 A열만 참조하는 헤더 설명을 대체한다. #177은 운영 시트를 변경하지 않는다. seed-sheet.mjs는 실행하지 않는다. 기존 초기화 스크립트는 기존 형식을 생성하므로 #178의 이전 도구로 사용할 수 없다.

1. 불변 ID와 생애주기

종목 정의는 id(고유·불변)와 name(표시용)으로 나뉜다. 표시 이름은 중복 가능하지만 ID는 중복 불가다. 목표 기준이 바뀌면 기존 종목에 종료 회차를 기입하고 새 ID로 새 행을 등록한다. 이름 변경만으로 ID를 다시 생성하거나 기존 행을 다른 종목으로 재사용하지 않는다. 종료 행과 과거 기록은 삭제하지 않는다. 회차별 목표 버전은 도입하지 않는다.

ID는 대소문자와 유니코드 표현까지 정확히 비교하는 opaque 문자열이다. 1~128자, 앞뒤 공백·제어문자 금지, __proto__·constructor·prototype 금지. 신규 종목에는 한 번 생성해 저장한 evt_<UUID>를 권장한다. 현재 이름의 해시/slug를 매번 계산하지 않는다.

2. 목표 탭 스키마

열헤더의미
A종목표시용 name. 기존 헤더명은 유지한다.
B목표기존 값 정규화·달성 판정 유지
C만점기존 의미 유지
D방향높을수록 / 낮을수록
E종료 회차빈칸/-은 현역, 날짜는 마지막 측정 회차(포함)
F면제 가능가능 / 빈칸 / -. 기존 5열 시트도 수용
G종목 ID이 헤더가 있으면 모든 유효 종목 행에 ID 필수. 빈 ID를 임시 ID로 대체하지 않는다.
H이전 종목명선택 열. 이전 중 고정 이름 헤더를 해석하기 위한 불변 이름 별칭 1개. 빈칸이면 없음. G 없이 사용 불가.

G/H의 알 수 없는 헤더, 헤더 없이 존재하는 값, 중복 ID는 명확한 오류다. I열 이후는 미래 확장을 위해 무시한다. 시트 직접 편집에서 ID의 불변성을 보장하려면 #178에서 G열을 보호해야 한다. 코드는 이전 상태 저장소가 없으므로 운영자가 기존 ID를 직접 덮어쓴 행의 변경 이력까지 판별할 수 없다.

3. 회차 헤더: 한 행 안에 ID와 이름

A1은 계속 이름이고 선수 데이터는 계속 2행부터다. 새 ID 형식의 B1 이후는 id:<정확한 ID>\n<표시 이름>이다. 첫 줄만 연결 기준이며 둘째 줄의 예전 이름이나 동명 여부는 기록 연결에 영향을 주지 않는다. ID만 있는 id:<ID>도 읽을 수 있다. id:로 시작하면 반드시 ID 헤더로 해석하며 이름으로 재시도하지 않는다.

="id:evt_123"&CHAR(10)&INDEX('목표'!A:A,MATCH(TRUE,ARRAYFORMULA(EXACT("evt_123",'목표'!G:G)),0))

첫 줄 ID는 생성 시 고정 리터럴로 저장한다. 둘째 줄만 목표 G열에서 ID를 찾아 A열 이름을 조회한다. 단순 =목표!G행 참조는 목표 행을 바꿨을 때 과거 점수의 정체성도 바꿀 수 있어 사용하지 않는다. EXACT를 사용해 대소문자를 구분하고 와일드카드를 해석하지 않는다. 수식 문자열의 쌍따옴표는 이스케이프한다. 이름 조회 실패는 시트 오류로 드러나며 다른 종목으로 대체하지 않는다.

기존 목표 탭에 G1이 없으면 새 회차도 기존 ='목표'!A행 헤더를 생성한다. 따라서 코드만 먼저 배포해도 기존 시트 읽기·쓰기·회차 생성이 유지된다. G1 추가 후 생성되는 회차부터 ID 헤더를 쓴다. 행 오프셋과 점수 범위가 바뀌지 않아 참가자 추가도 기존 방식 그대로 동작한다.

4. 호환 및 매핑 규칙

  1. G1 없는 5/6열 목표 탭: 원본 시트 행 번호 N에서 legacy-row-N을 사용한다(헤더=1행, 첫 종목=legacy-row-2). 중간 빈 행을 건너뛰어도 번호를 압축하지 않는다. 이름은 ID 생성에 관여하지 않는다. 기존 규칙인 목표 행 정렬·이동·삽입·삭제 금지를 유지하고 신규 종목은 맨 아래에만 추가한다.
  2. G1 있는 목표 탭: G의 저장된 ID를 사용한다. 일부 행만 이전된 상태는 오류이며 임의의 fallback을 하지 않는다.
  3. ID 회차 헤더: 정확히 해당 ID 하나에 연결한다. 같은 ID가 회차에 두 번 등장하거나 목표에 존재하지 않으면 오류다.
  4. 이름 회차 헤더: trim + NFC한 이름이 목표 name 또는 legacyName과 일치하는 종목이 정확히 하나일 때만 연결한다. 두 개 이상이면 종료일·목표값·행 순서로 추정하지 않는다. ID/이름 헤더가 혼재해도 동일 ID 중복은 오류다.
  5. 기존 수식 헤더는 A열 이름 변경을 따라가므로 legacy ID를 그대로 유지한다. 직접 입력된 고정 이름 헤더는 ID로 전환하거나 H열 별칭을 먼저 저장한 뒤 이름을 변경해야 한다. ID도 별칭도 없는 과거 문자열에서 변경 이력을 복원할 수는 없다. 모호해진 경우 저장 전 차단한다.
  6. 동명 종목을 추가하기 전에 관련 과거 이름 헤더를 모두 ID 헤더로 바꾼다. H 별칭도 동일 이름의 신규 종목과 충돌할 수 있으므로 날짜로 구분하지 말고 ID 헤더 이전을 완료한다.

5. API 계약과 화면

경로새 계약
events[]key 제거 → id, name, 선택 legacyName. 목표·종료·면제 필드 유지.
sessions[]eventKeys 제거 → eventIds. 실제 헤더 순서.
entries[].scores / POST scores속성 이름은 정확한 종목 ID. 해당 회차 종목 전체를 빠짐없이 보내야 함. 이름 요청을 ID 요청으로 추정하지 않음.
rankings[].events[].event / trends[].event / personalBests[].event / home.achievementRates[].event필드명 event는 유지하되 값은 ID. 표시는 events의 name 조회.

프론트 런타임 검증은 ID/이름, ID 중복, 회차/점수의 ID 집합, 랭킹·추이·최고기록·홈의 ID 참조를 검증한다. 시트 매핑 오류는 500 sheet_data_invalid, 요청 ID 누락/미지/값 오류는 400 validation_failed이며 쓰기 전에 차단한다. 정상 저장은 ID 순서가 아니라 물리적 헤더 열 순서로 점수 값을 배치한다.

화면의 선택 상태와 입력 상태도 ID 기준이다. 동명 종목에는 종료/진행 상태와 실제 측정 회차의 첫 날짜~마지막 날짜를 표시한다(목표 버전 기간 아님). 측정 전은 “측정 전”으로 표시한다. 종료 종목의 과거 랭킹·추이·최고기록을 유지한다.

6. #178 실행 및 배포 순서

  1. 운영 변경 권한과 별도 작업 시간을 확보한다. 원본의 값·수식·서식·보호 설정을 백업하고 복제 시트에서 먼저 검증한다. #177에서는 이 작업을 수행하지 않았다.
  2. #177의 프론트와 Functions를 함께 배포한다. 응답 캐시 키는 v2 → v3로 변경되어 구형 이름 기반 캐시를 재사용하지 않는다. 열린 구형 브라우저 탭은 새로고침해야 한다. 예전 POST 이름 키는 임의 변환하지 않아 400이 발생할 수 있으나 다른 종목에 저장되지는 않는다.
  3. 아직 시트를 바꾸지 않은 상태에서 5/6열 읽기·기록 저장·새 회차 생성이 동작하는지 복제 환경에서 검증한다. 운영 배포와 확인은 #178 담당자가 별도 진행한다.
  4. 쓰기/수기 편집을 잠시 중지한다. 모든 목표 행·종료 종목을 포함한 원본 행 → legacy-row-N → 현재 이름 → 별칭 → 참조 회차/열 매핑 명세를 만든다. 모든 이름 헤더가 정확히 한 종목에 매핑되는지 사전 검사한다. 미지/중복 이름·중복 ID·불완전 데이터는 중단하고 관리자가 해결한다.
  5. G1과 모든 G 값은 한 원자적 배치로 추가한다. 기존 종목에는 기존 응답의 legacy-row-N 값을 그대로 영구 저장하여 배포/이전 전후 API ID도 유지한다. 임시라는 이유로 UUID로 다시 바꾸지 않는다. 필요 시 H에 기존 이름을 저장한다. ID는 숫자/날짜로 자동변환되지 않도록 문자열로 기록한다.
  6. 모든 회차의 종목 헤더를 승인된 매핑에 따라 고정 ID+이름 조회 수식으로 변경한다. 점수 셀·선수 행·열 순서는 변경하지 않는다. 목표와 회차 전체를 원자적으로 바꾸거나, 쓰기 중지 상태에서 분할하되 혼재 읽기 검증을 실시한다.
  7. G열/회차 헤더를 보호한다. 기존 명단/목표 행 이동 금지는 남은 행 참조 수식이 없는지 확인하기 전까지 유지한다. 이름 변경 실험, 동명·다른 ID 실험은 복제 시트에서 먼저 진행한다.
  8. 이전 전후 참가자 수·회차별 eventIds·점수 원값·랭킹·추이·최고기록·달성률을 비교한다. 캐시를 무효화하고 새 조회를 검증한 뒤 쓰기를 재개한다. 동명 신규 종목 등록(#179/#181)은 이 검증 이후다.

롤백: ID 헤더 도입 후에는 구코드만 단독 롤백하면 읽을 수 없다. 쓰기 중지 → 변경 후 점수 백업 → 이전 전 목표/헤더 복구 또는 신코드 수정 배포 → 정합성 검증 → 캐시 무효화 순서로 복구한다. 이전 후 쌓인 점수를 과거 스냅샷으로 덮어쓰지 않는다. 코드만 먼저 배포한 단계에서는 시트가 기존 형식이므로 프론트/백엔드를 함께 구버전으로 되돌릴 수 있다.

7. 검증 및 범위

순수 통합 테스트는 두 ID의 동명 종목, 이름 변경·행 재배치, 종료 기록, 기존/신규 헤더 읽기·쓰기·생성, 별칭, 빈 행 ID, 모호성·중복·미지 ID와 런타임 참조 무결성을 검증한다. API 테스트는 기존 시트의 ID 요청 저장, 동일 이름 열의 순서 보존, 잘못된 매핑 시 쓰기 차단, 신규 회차의 ID 수식을 검증한다. 프론트 테스트는 표시 이름과 전송 ID가 분리됨을 검증한다.

검증 명령: npm test -- --maxWorkers=4, npm run typecheck, npm run build. Google Sheets I/O는 모킹한다. 실제 Sheets 수식 평가·운영 권한·보호 설정은 #178 복제 시트 검증의 필수 단계다.

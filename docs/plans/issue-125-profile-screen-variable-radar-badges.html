1요약

선행 이슈 #118(PR #140)이 이미 profile-view.ts의 데이터 파생 절반을 끝내놨다 — buildRadarAxes는 session.eventKeys 기준으로 축을 순회해 회차마다 4각형↔7각형으로 가변하고, buildGrowthCards는 종료 종목을 유효 기록 보유 선수에게만 ended: true 카드로 내려준다. 다만 PR #140의 커밋 메시지가 명시하듯 "뱃지 렌더는 후속 #125"로 미뤄뒀고, radar-math가 N축 일반이라는 사실도 4축 케이스로만 테스트돼 있다. 이번 이슈는 나머지 절반 — ① GrowthStatCard에 실제 종료 뱃지 렌더 ② radar-math·RadarChart의 7축 구조 검증 — 을 마무리한다. 화면 조립(Players.tsx)과 추이 차트는 변경이 필요 없다.

2현황 분석

데이터 파생(완료, #118/PR140):

  • src/lib/profile-view.ts:27-43 buildRadarAxes — 전역 events[]가 아니라 session.eventKeys를 순회해 축을 만든다. 세션이 없으면 빈 배열.
  • src/lib/profile-view.ts:53-63 GrowthCardDatum에 ended: boolean 필드가 이미 존재하고, 주석이 "카드 뱃지 렌더는 #125 스코프"라고 명시한다.
  • src/lib/profile-view.ts:95-113 buildGrowthCards — events.filter((event) => event.endSessionDate === null || pbByEvent.has(event.key))로 현역 종목 전부 + 종료 종목 중 유효 PB 보유 종목만 남기고, 각 카드에 ended: event.endSessionDate !== null을 채운다.
  • src/lib/profile-view.test.ts:182-224에 4축/7축 buildRadarAxes 회귀 테스트, :274-307에 종료 카드 노출 조건 테스트가 이미 있다 — 데이터 레이어는 완전히 검증돼 있다.

  • src/components/charts/radar-chart.tsx:26-74 RadarChart도 axes.length를 그대로 ringPoints/polygonPoints/radarPoint에 넘겨 N축 일반이다. 배경 링 개수(RING_COUNT = 4, 17행)는 축 개수와 무관하게 고정 4개.
  • src/components/charts/radar-chart.test.tsx도 4축 픽스처(8-13행)만 사용 — 7축 렌더 구조(도트·라벨 개수, aria-label 문구)를 확인한 테스트가 없다.

디자인 근거: docs/prd-event-lifecycle.html §08 라인 319-320 — "레이더 축 = 선택 회차의 측정 종목 … radar-math는 이미 N축 일반이므로 7축 시각 검증만 필요" / "종료 종목은 … 카드에 종료 뱃지를 단다". 같은 문서 마이그레이션 시나리오(라인 382)가 기대 화면을 명시: "1차(4종목) 참가자는 45도패스캐치 성장 카드를 종료 뱃지와 함께 보고, 그 외 선수에겐 카드 자체가 없다."

뱃지 스타일 컨벤션: 이 레포는 상태 뱃지를 전부 Pill 공용 컴포넌트(src/components/Pill.tsx)로 만든다 — PlayerStatusPill·EntryStatusPill·AchievementBadge가 전부 동일 패턴(<Pill colorClassName="bg-*-tint text-*-strong">텍스트</Pill>). "미측정"류 중립 상태는 전부 bg-neutral-tint text-neutral-strong(EntryStatusPill.tsx:10, RankingRow.tsx:47) — "종료"도 달성/실패가 아닌 생애주기 상태이므로 같은 neutral 톤이 맞다.

3설계

  • 뱃지 배치: GrowthStatCard 헤더 좌측 컬럼(라벨+PB)에서 라벨 옆에 인라인으로 종료 Pill을 card.ended일 때만 렌더한다. 우측 컬럼(현재값/델타)은 손대지 않는다 — PRD가 뱃지 위치를 못박지 않았고, 다른 화면(랭킹)도 이름 옆 상태 뱃지 패턴을 쓰므로 동형을 유지한다.
  • 색 톤: bg-neutral-tint text-neutral-strong (기존 Pill 재사용, 새 컴포넌트 불필요 — AchievementBadge처럼 별도 래퍼를 만들 수도 있지만 "종료"는 이분법 매핑이 아니라 조건부 존재이므로 GrowthStatCard 안에서 직접 {card.ended && <Pill>...</Pill>}로 충분하다).
  • 레이더 검증 방식: 이슈가 "스크린샷 또는 구조 검증"을 모두 허용하고, 이 레포에 시각 회귀 도구(Storybook/Playwright 등)가 없다 — radar-math·RadarChart 둘 다 7축 좌표/구조를 결정론적으로 단언하는 단위 테스트로 검증한다(기존 4축 테스트와 동일 스타일, PR #140의 검증 방식과 동형). 계산값은 axisAngle(i,7) = 2π·i/7 - π/2 공식을 그대로 수치화해 미리 계산해둔다.

4작업 단계

  1. radar-math 7축 구조 검증 — 기존 4축 describe 옆에 7축 radarPoint 좌표(반지름 80·중심 100 기준, axisAngle 공식으로 사전 계산한 7개 좌표) 및 radarLabelLayout anchor/baseline 7축 케이스를 추가했다. Python으로 axisAngle 공식을 직접 재계산해 기대값을 뽑았고, 8개 테스트 전부 그린. src/components/charts/radar-math.test.ts
  2. RadarChart 7축 렌더 구조 검증 — 7개 종목 axes 픽스처로 렌더해 도트 7개·라벨 텍스트 7개(순서 유지)·aria-label에 7개 항목 모두 포함·배경 링은 여전히 4개(축 개수와 무관)임을 단언하는 테스트 3개를 describe('7축(가변 축 상한 케이스)')로 추가했다. src/components/charts/radar-chart.test.tsx
  3. GrowthStatCard에 종료 뱃지 렌더 — Pill을 import해 라벨 옆(flex row)에 card.ended일 때만 <Pill colorClassName="bg-neutral-tint text-neutral-strong">종료</Pill>를 렌더한다. 계획대로 별도 래퍼 컴포넌트 없이 기존 Pill 재사용. src/components/GrowthStatCard.tsx
  4. GrowthStatCard 뱃지 테스트 — ended: true 카드는 "종료" 텍스트가 렌더되고, ended: false(기존 CARD 픽스처)는 렌더되지 않음을 검증하는 테스트 2개를 추가했다. src/components/GrowthStatCard.test.tsx
  5. 수동 확인(베스트에포트) — 계획에서 예상한 대로 생략. /api/records는 실제 구글 시트 연동(wrangler pages dev + 시크릿)이 필요한데 이 워크트리 샌드박스엔 자격증명이 없어 Players.tsx를 실데이터로 띄워볼 수 없다. 구조 검증 테스트(위 1·2단계)로 완료 조건을 충족한 것으로 본다 — 이슈 문구가 "스크린샷 또는 구조 검증"을 명시적으로 허용. 스킵 — 사유: 로컬에 records API 자격증명 없음

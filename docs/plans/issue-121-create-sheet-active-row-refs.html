P7 — create-sheet: 현역 종목 필터 + 목표 탭 실제 행 번호 참조 수식

damdam6/bernice 브랜치 feat/121-create-sheet-active-row-refs ← main 라벨 enhancement 2026-07-27

1요약

회차 탭 생성(POST /api/admin/create-sheet)이 목표 탭 전체 종목으로 헤더를 만들고, 참조 수식도 "목표 탭이 빈 행 없이 연속"이라는 가정(=목표!A{인덱스+2}) 위에 지어져 있다. 종목 생애주기(#111)로 목표 탭에 종료 종목이 섞여 들어가면 이 가정이 깨진다 — 신규 회차에 종료 종목이 계속 포함되고, 종료 종목이 중간에 끼면 뒤따르는 현역 종목의 참조 수식이 엉뚱한 행을 가리킨다. #111이 이미 parseGoals에 종목별 실제 행 번호(sheetRowByKey)를 동반해뒀으므로, 이번 이슈는 그 값을 create-sheet 경로까지 배선하고 헤더를 현역 종목만으로 좁히는 배선 작업이다.

2현황 분석

파서 쪽은 이미 준비돼 있다. functions/lib/parse-goals.ts:24-52의 parseGoals는 { events, sheetRowByKey }를 반환한다 — sheetRowByKey: Map<string, number>는 종목 key → 그 종목의 목표 탭 실제 행 번호(헤더 다음부터, 스킵된 빈 행이 있어도 밀리지 않는 원본 위치 기준)다. 이 파일의 docblock(parse-goals.ts:12-13)이 명시적으로 "create-sheet(#121)가 헤더 참조 수식을 지을 때 쓴다"고 적어뒀다.

배선이 안 된 지점 — 엔드포인트. functions/api/admin/create-sheet.ts:71은 const { events } = parseGoals(goalsRange.values)로 events만 꺼내 쓰고 sheetRowByKey는 버린다. 그 아래 buildCreateSheetPlan 호출(create-sheet.ts:73-81)에도 넘기지 않는다.

배선이 안 된 지점 — 순수 로직. functions/lib/create-sheet.ts:

  • BuildCreateSheetParams.events(create-sheet.ts:26-27)에 sheetRowByKey 필드 자체가 없다.
  • buildCreateSheetPlan(create-sheet.ts:79)이 events를 필터 없이 그대로 buildBatchRequests에 넘긴다 — 종료 종목도 헤더에 들어간다.
  • buildBatchRequests의 헤더 조립(create-sheet.ts:97-100)이 events.map((_, index) => ...=${goalsRef}!A${index + 2})로 "목표 탭이 연속"이라는 가정을 그대로 코드화하고 있다 — 이 주석(create-sheet.ts:95-96) 자체가 "목표 탭이 빈 행 없이 연속이라는 전제는 시딩·파서와 동일"이라고 명시해, 스스로 전제를 깨는 순간(종료 종목 등장)을 예고하고 있다.

도메인 타입 근거. shared/domain.ts:45-47 — EventDefinition.endSessionDate: string | null, null이면 현역. events[]는 종료 종목을 포함한 전체를 목표 탭 행 순서대로 담는다(과거 랭킹·추이가 종료 종목 정의를 필요로 하므로).

테스트 현황. functions/lib/create-sheet.test.ts와 functions/api/admin/create-sheet.test.ts 둘 다 현재 모든 EventDefinition 픽스처의 endSessionDate: null이고, 목표 탭 행이 항상 연속이라 지금 버그가 테스트로는 드러나지 않는다.

3설계

필터·참조 로직은 create-sheet.ts(순수 로직)에 둔다 — 활동 참가자 필터(activeById)·가나다 정렬처럼 이미 이 파일이 "회차 탭 생성 규칙"의 단일 소유자이기 때문. 엔드포인트는 I/O 배선만 담당하는 현재 역할 분담(파일 최상단 docblock)을 그대로 지킨다.

  • 현역 필터: buildCreateSheetPlan 진입 시 events.filter(e => e.endSessionDate === null)로 좁힌 뒤 그 결과만 헤더 조립에 넘긴다. 참고: EventDefinition 목록 순서(목표 탭 행 순서)는 필터 후에도 유지되므로 헤더 종목 순서는 자연히 "현역 종목의 목표 탭 등장 순서"가 된다.
  • 행 번호 참조: BuildCreateSheetParams에 sheetRowByKey: Map<string, number>를 추가한다. 헤더 셀 수식을 =${goalsRef}!A${index + 2} 대신 =${goalsRef}!A${sheetRowByKey.get(event.key)}로 짓는다.
  • 존재하지 않는 key 처리: sheetRowByKey는 같은 parseGoals 호출이 만든 events와 1:1 대응이 보장되는 내부 부산물이라(파일 docblock, parse-goals.ts:12-13) 필터링된 events의 모든 key는 항상 맵에 존재한다. 기존 activeById.get(id)!(create-sheet.ts:66)와 같은 관용구로 non-null 단언 + 불변식 설명 주석을 단다 — 방어적 에러 처리를 새로 만들지 않는다(그 불변식이 깨지는 경우는 parseGoals 자체 버그이지 create-sheet의 책임이 아님).
  • 기각한 대안 — 인덱스 재계산: 필터링된 events 배열 안에서 위치를 다시 세거나 원본 배열의 인덱스를 추적하는 방식은 "행 번호는 시트 위치"라는 사실을 코드에서 다시 유도하는 것이라, parse-goals가 이미 확정해준 값과 어긋날 여지(중간에 빈 행 스킵 등)를 새로 만든다 — 그냥 sheetRowByKey를 신뢰하는 쪽이 단순하고 정확하다.

나머지(참가자만·가나다 정렬·빈 점수·원자적 batchUpdate·오늘 중복 가드·캐시 무효화, 명단 참조 수식 로직)는 이슈 스코프 밖 — 변경 없음.

4작업 단계

  1. 엔드포인트가 sheetRowByKey를 꺼내 buildCreateSheetPlan에 넘기도록 배선 functions/api/admin/create-sheet.ts
  2. BuildCreateSheetParams에 sheetRowByKey: Map<string, number> 필드 추가, JSDoc으로 출처(parse-goals) 명시 functions/lib/create-sheet.ts
  3. buildCreateSheetPlan에서 events를 endSessionDate === null로 필터링한 뒤 buildBatchRequests에 전달 — 필터링된 목록을 응답 계약에 새로 노출할 필요는 없음(현재도 events는 반환 안 함) functions/lib/create-sheet.ts
  4. buildBatchRequests의 헤더 조립을 index + 2 대신 sheetRowByKey.get(event.key)! 기반으로 교체, 관련 주석(연속 전제 문구) 갱신 functions/lib/create-sheet.ts
  5. create-sheet.test.ts에 현역 필터 테스트(종료 종목 제외 확인)와 비연속 행 참조 테스트(중간에 종료 종목이 낀 픽스처로 A열 행 번호가 실제 시트 위치를 그대로 반영하는지 확인) 추가 — 기존 테스트의 EVENTS/BASE 픽스처에 sheetRowByKey 동반 functions/lib/create-sheet.test.ts
  6. create-sheet.test.ts(엔드포인트 통합 테스트)의 GOALS_VALUES 픽스처에 종료 종목 행을 섞어 넣고, 응답으로 만들어지는 헤더 수식이 현역 종목만·실제 행 번호를 참조하는지 확인 functions/api/admin/create-sheet.test.ts
  7. 전체 테스트·타입체크·린트 실행, 회귀 없는지 확인 package.json 스크립트(test/typecheck/lint)

5리스크

리스크영향완화책
모든 종목이 종료돼 현역 종목이 0개인 경우 헤더가 "이름" 한 열만 남음극단적 운영 상황(전 종목 종료) — 현재 스펙엔 별도 가드가 없음이슈 스코프 밖으로 판단(비스코프 §12에도 언급 없음) — 발생 시 빈 헤더 그대로 생성되고 별도 후속 이슈로 다룬다. 테스트로 최소 회귀만 확인
sheetRowByKey에 key가 없는 상태로 ! 단언이 실행되는 경우런타임 undefined → 잘못된 수식(=목표!Aundefined) 생성같은 parseGoals 호출의 events·sheetRowByKey는 항상 1:1(파서 자체 불변식) — 엔드포인트가 항상 같은 호출 결과의 두 값을 함께 넘기도록 스텝 1에서 배선

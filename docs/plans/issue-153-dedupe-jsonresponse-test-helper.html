1요약

한 줄짜리 테스트 헬퍼 jsonResponse(status, body)가 19개 테스트 파일에 로컬로 복붙돼 있다. 19곳 전부 본문이 바이트 단위로 동일함을 확인했으므로, 기존 공용 유틸 위치인 src/test/에 json-response.ts를 신설하고 로컬 정의 전부를 import로 일괄 교체한다. 동작 변경이 없는 순수 기계적 리팩토링이며, 기준선(테스트 파일 86개 · 테스트 779개 전체 그린)이 그대로 유지돼야 한다.

2현황 분석

로컬 정의 19곳을 전수 확인한 결과, 본문이 전부 동일하다:

function jsonResponse(status: number, body: unknown): Response { return new Response(JSON.stringify(body), { status }) }

  • 분포 (디렉터리별): src/App.e2e.test.tsx:64 1곳 · src/components/auth/ 2곳 (AdminGate.test.tsx:24, LoginGate.test.tsx:24) · src/hooks/ 2곳 (useRecords.test.tsx:14, useRefreshRecords.test.tsx:14) · src/lib/ 5곳 (add-players-api.test.ts:8 등 전부 8행) · src/pages/ 3곳 (Home.test.tsx:15, Players.test.tsx:15, Rankings.test.tsx:15) · src/pages/admin/ 6곳 (AdminLogin.test.tsx:14, CreateSheet.test.tsx:15 등)
  • 공용 테스트 유틸 선례가 이미 있다: src/test/html-utils.ts는 named export 함수만 두는 평문 모듈이고, 사용처는 상대 경로로 import한다 (예: src/components/AchievementBadge.test.tsx:4의 import { renderClassName, renderText } from '../test/html-utils')
  • 경로 별칭 없음: tsconfig에 paths/baseUrl 설정이 없고 vite.config.ts/vitest.config.ts에도 alias가 없다 — 상대 경로 import가 이 레포의 유일한 관용구
  • vitest 설정은 environment: 'node' 단일이며(vitest.config.ts:5), 컴포넌트 테스트는 파일 상단 // @vitest-environment jsdom 프라그마를 쓴다. 두 환경 모두에서 Response 전역이 이미 로컬 정의로 사용되고 있으므로 이관해도 실행 환경 조건은 변하지 않는다
  • 기준선: npx vitest run → 테스트 파일 86개 · 테스트 779개 전체 통과 (2026-07-28 워크트리에서 실측)

3설계

  • 파일명 src/test/json-response.ts (이슈 본문의 예시안 그대로): html-utils.ts처럼 단일 관심사 파일로 둔다. 리뷰 코멘트의 test-utils.ts 통합안은 기존 html-utils.ts와 역할이 겹치는 잡동사니 파일이 되므로 기각 — 이 레포의 선례는 유틸별 파일 분리다
  • export 형태: export function jsonResponse(status: number, body: unknown): Response named export. 본문은 기존 19곳과 바이트 동일하게 유지해 동작 불변을 보장한다
  • import 경로: 별칭이 없으므로 디렉터리 깊이별 상대 경로 3종 — ./test/json-response (src 루트 1곳) · ../test/json-response (hooks·lib·pages 10곳) · ../../test/json-response (components/auth·pages/admin 8곳)
  • import 위치: 각 파일의 기존 import 블록 말미(상대 경로 import 군)에 추가 — html-utils 사용처와 같은 배치
  • vitest 수집 안전성: vitest 기본 include는 *.test.*/*.spec.* 패턴이므로 src/test/json-response.ts가 테스트 파일로 오인 수집될 여지는 없다 (html-utils.ts가 동일 위치에서 이미 검증된 사실)

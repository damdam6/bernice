#174버그 수정

기록이 희소한 선수의 추이 차트가 깨져 보임 — 좁은 도메인 + 배경 라인 클립 세로 막대

damdam6/bernice 브랜치 fix/174-sparse-trend-chart-domain ← main 라벨 bug 2026-07-30

1요약

기록이 희소한 선수(본인 점 1개 + 목표)의 추이 차트가 "절벽 + 좌측 세로 막대"로 깨져 보인다. 원인은 둘 다 #172에서 도입한 원값 도메인의 엣지 미처리다 — trendDomain이 폭 2.3초짜리 범위를 카드 높이로 늘리고, 그 좁은 창을 즉시 벗어나는 팀원 배경 라인이 clipPath에 잘려 거의 수직인 토막만 남는다. 고치는 방향은 (1) 도메인 최소 폭 보장을 값 대비 비율로 일반화(현행 min === max 폴백을 이 규칙의 특수 케이스로 흡수), (2) 도메인과 교차하는 구간이 없는 배경 시리즈는 렌더 자체를 생략, (3) 본인 recorded 0건이면 빈 좌표축 대신 빈 상태 문구. #172의 D1~D3(원값 축 · 반전 없음 · 클램프 금지 · 목표 항상 포함)은 한 줄도 건드리지 않는다.

2현황 분석

추이 차트는 결합 → 도메인 → 좌표 → 렌더 4층이고, 이번 버그는 도메인 계산과 렌더 사이의 엣지에서만 발생한다. 데이터 결합층은 이번 변경 대상이 아니다.

  • 결합 — src/pages/Players.tsx:107이 확장된 카드에 대해서만 buildTrendSeries(event, sessions, players, player.id)를 부르고, src/lib/profile-view.ts:145-152가 본인 highlight(recorded 점만, 희소 허용) · 타인 background(빈 시리즈는 이미 제외) · goal = event.targetValue를 원값 그대로 넘긴다.
  • 도메인 — src/components/charts/trend-math.ts:52-76의 trendDomain(highlight, goal, background)이 본인 recorded 값 ∪ 목표값의 min~max에 PAD_RATIO = 0.08을 붙인다. 배경 값은 범위 계산에서 제외된다(#172 D3, src/components/charts/trend-math.ts:60-66은 본인 점도 목표도 없을 때만 배경 extent로 폴백).
  • 좌표 — src/components/charts/trend-math.ts:81-86의 trendY는 도메인 선형 매핑이고 범위 밖 값을 클램프하지 않는다(#172 D3 — 가장자리 클램프는 값 왜곡). 밴드 밖 좌표를 그대로 내고 잘라내는 책임은 호출자에게 있다.
  • 렌더 — src/components/charts/trend-chart.tsx:51-66이 플롯 밴드(y = padTop … padTop + bandHeight) 크기의 clipPath를 만들어 배경 라인 <g>에만 걸고, background.map으로 받은 시리즈를 전부 <polyline>으로 그린다. 가시성 판정은 없다 — 클립이 알아서 지워줄 것이라는 가정이다.
  • 엣지 처리 현황 — trendDomain에는 min === max 폴백 하나뿐이다(src/components/charts/trend-math.ts:70-73, FLAT_HALF_RATIO = 0.1 · 최소 반경 1). TrendChart의 조기 반환도 sessionLabels.length === 0 하나뿐이다(src/components/charts/trend-chart.tsx:39) — 본인 점 0개는 어디에도 걸리지 않아 도트도 선도 없는 좌표축이 그려진다.
  • 테스트 현황 — src/components/charts/trend-math.test.ts(도메인·좌표·폴리라인) · src/components/charts/trend-chart.test.tsx(렌더·클립·목표선)가 #172에서 갱신됐다. src/pages/Players.test.tsx:192는 role="img" 존재만 보고 값은 보지 않으며, 픽스처의 두 선수 모두 확장 종목에 recorded 점이 있어 빈 상태 경로를 타지 않는다.

3원인 분석

재현 사례(드리블셔틀런 PB 1:15 = 75초, 목표 1:17 = 77초, 2차 미측정)를 현재 코드에 그대로 넣으면 두 증상이 같은 하나의 값에서 파생된다.

원인 1 · 도메인 폭 2.32초가 카드 높이로 확대

  • trendDomain([{75}], 77) → min 75 · max 77 → pad = 2 × 0.08 = 0.16 → {74.84, 77.16} (폭 2.32초). 이 2.32초가 밴드 122px에 매핑되므로 1초 ≈ 53px이다. 2초 차이가 절벽처럼 보이는 이유.
  • min === max 폴백이 발동하지 않는 것이 핵심이다 — 목표값 77이 값 배열에 들어가 min ≠ max가 되기 때문(src/components/charts/trend-math.ts:58, :70). 즉 "본인 점 1개 + 목표" 조합은 현재 어떤 엣지 분기에도 걸리지 않는 사각지대다.

원인 2 · 클립이 남긴 거의 수직인 토막

  • 팀원 값(예: 90·95·110초)은 그 2.32초 창을 한참 벗어난다. trendY가 클램프하지 않으므로 좌표는 밴드 위로 수백 px 튀고(src/components/charts/trend-math.ts:85), clipPath는 밴드와 겹치는 부분만 남긴다.
  • 1차 점만 밴드에 가까운 시리즈들이 겹치면 x = 1차 근방의 짧은 수직 선분 여러 개가 남아 연보라 세로 막대로 읽힌다. 데이터상 "팀원은 화면 밖"인데 화면에는 렌더 버그로 보인다.
  • 진짜 결함은 "가시 구간이 없는 시리즈도 무조건 <polyline>을 낸다"는 점이다(src/components/charts/trend-chart.tsx:57-65). 클립은 부분적으로 보이는 선을 자르는 도구이고, 전혀 보이지 않아야 하는 선을 지우는 도구가 아니다.

설계 결정

  • E1 · 최소 도메인 폭 — FLAT_HALF_RATIO(0.1) + 최소 1을 MIN_SPAN_RATIO(0.2) + MIN_SPAN_ABS(2)로 이름·의미를 바꾸고, 분기 조건을 min === max에서 span < minSpan으로 넓힌다(중앙 기준 대칭 배치). 비율 기반이라 초/개 단위에 무관하다.
    수치가 정확히 하위 호환이라는 점이 이 상수 선택의 근거다: 폭 0일 때 2 × (0.1 × |v|) = 0.2 × |v|, 절대 하한도 2 × 1 = 2로 같다. 기존 폴백은 새 규칙의 특수 케이스로 흡수되고, 기존 도메인 테스트 기대값({72, 88} · {-1, 1} · {56.8, 103.2} …)이 한 줄도 바뀌지 않는다. 재현 사례는 {68.4, 83.6}(폭 15.2초)이 되어 도트 y≈81 · 목표선 y≈65로 자연스럽게 벌어진다.
  • E2 · 가시 구간 판정 — hasVisibleSegment(points, count, domain)을 trend-math.ts에 순수 함수로 추가한다. 점 하나라도 도메인 안이면 가시, 인접한 두 점이 위/아래로 도메인을 가로지르면 밴드 안에 선분이 남으므로 가시, 전부 위 또는 전부 아래면 비가시. 비가시 시리즈는 TrendChart가 렌더에서 제외한다 — 클램프는 여전히 쓰지 않으므로 #172 D3 불변.
  • E3 · 본인 0건 = 빈 상태 — 판정 기준을 highlight.length가 아니라 렌더 가능한 점 수(0 ≤ sessionIndex < count)로 둔다. 그래야 "그려질 게 없다"와 문구 노출이 정확히 일치한다. 문구는 TrendChart가 직접 반환해 호출자(Players.tsx)를 건드리지 않고 모든 호출자에 일관되게 적용한다. 카드 헤더(PB·현재값·델타)는 GrowthStatCard 소관이라 자동으로 그대로다.

배제한 대안

  • 배경 값을 도메인에 포함 — 타인 극단값 1건이 본인 점 위치를 재배치하는 #172의 원래 버그로 되돌아간다.
  • 범위 밖 배경 값 클램프(가장자리 붙이기) — 이슈가 명시적으로 금지(#172 D3, 값 왜곡).
  • 절대 최소 폭 상수만 사용(예: "최소 5초") — 개수 종목(5개 만점)에서 전 범위를 덮어버린다. 종목 단위 무관 요구와 충돌.
  • 본인 점 1개도 빈 상태로 — 목표 대비 위치라는 정보가 있으므로 이슈가 도트 + 목표선 유지를 요구.
  • clipPath 제거하고 세그먼트 클리핑 직접 구현 — 부분 가시 구간의 정확한 절단은 지금도 clipPath가 올바르게 하고 있다. 판정만 추가하는 게 최소 변경.

4작업 단계

  1. 최소 도메인 폭 일반화 — FLAT_HALF_RATIO를 MIN_SPAN_RATIO = 0.2 · MIN_SPAN_ABS = 2로 대체하고, trendDomain의 min === max 분기를 span < minSpan(중앙 기준 대칭)으로 넓힌다. 주석에 "기존 동률 폴백을 흡수한 규칙 · 비율 기반이라 단위 무관"과 수치 하위 호환 근거를 남긴다. src/components/charts/trend-math.ts
  2. hasVisibleSegment 추가↳ 계획보다 한 걸음 더 — 공용 필터를 renderablePoints로 export해 TrendChart의 도트 렌더에 있던 같은 필터 중복까지 제거했다. — 도메인 대비 각 점의 위치(위/안/아래)를 훑어 안이 하나라도 있거나 인접 점이 위↔아래로 교차하면 true. 렌더 인덱스 필터(0 ≤ sessionIndex < count)는 polylinePoints와 공용 헬퍼로 뽑아 판정과 렌더가 같은 점 집합을 보게 한다. 비유한 값은 trendY가 밴드 중앙에 두므로 가시로 취급(판정이 실제 렌더보다 더 많이 숨기지 않도록 보수적으로). src/components/charts/trend-math.ts
  3. 배경 라인 가시성 필터 — TrendChart가 background를 hasVisibleSegment로 걸러 렌더한다. clipPath·그리기 순서·스트로크 스펙은 그대로(§07). src/components/charts/trend-chart.tsx
  4. 본인 0건 빈 상태↳ 문구 확정 — <p class="py-8 text-center text-sm text-ink-sub">아직 기록이 없습니다</p>. 덧붙여 trendDomain에도 인덱스 필터를 통과한 점만 넘겨 도메인·폴리라인·도트·빈 상태가 같은 점 집합을 본다. — 렌더 가능한 highlight 점이 0개면 <svg> 대신 짧은 문구를 반환한다. 레포의 인라인 보조 텍스트 톤(text-sm text-ink-sub 중앙 정렬)을 따르고, 무거운 EmptyState 카드는 카드 안에 중첩되므로 쓰지 않는다. src/components/charts/trend-chart.tsx
  5. trend-math 테스트 추가 — ① 1점 + 목표 도메인이 최소 폭까지 벌어지고 두 값이 중앙에 대칭 배치, ② 넓은 범위는 기존 8% 패딩 그대로(회귀), ③ 가시 구간 판정 4케이스(전부 위 / 전부 아래 / 일부 도메인 안 / 위↔아래 교차), ④ 렌더 인덱스 밖 점만 있는 시리즈는 비가시, ⑤ 개수 종목(작은 값)에서도 절대 하한이 동작. src/components/charts/trend-math.test.ts

5리스크

리스크영향완화책
최소 폭 상수 0.2가 넓은 범위 차트의 모양을 바꾼다기존 정상 차트가 눌려 보일 수 있다분기가 span < minSpan일 때만 발동하므로 넓은 범위는 기존 8% 패딩 경로 그대로다. 기존 도메인 테스트 기대값이 전부 그대로 통과하는 것으로 검증(수치 하위 호환은 상수 선택 근거이기도 하다).
가시성 필터가 보여야 할 배경 라인을 숨긴다#172의 "범위 밖 구간은 잘려 보인다" 의도가 훼손된다판정 기준을 "도메인과 교차하는 구간이 하나도 없음"으로 좁게 두고, 위↔아래 교차 시리즈는 가시로 유지한다. 비유한 값도 보수적으로 가시 처리. 4케이스 단위 테스트로 고정.

6테스트 계획

  • npm test — 전체 스위트 그린. 특히 trend-math.test.ts의 기존 도메인 기대값({72, 88} · {-1, 1} · {56.8, 103.2} · 목표 포함 · 배경 제외)이 수정 없이 통과해야 한다 — 통과하지 않으면 상수 선택이 하위 호환이 아니라는 신호다.
  • 도메인 최소 폭 — trendDomain([{75}], 77)의 폭이 max(0.2 × 76, 2) = 15.2이고 75·77이 중앙 대칭으로 놓인다. trendY로 두 y가 밴드 안이고 간격이 밴드 높이의 20% 미만(절벽 아님)임을 확인.
  • 개수 종목 절대 하한 — 작은 값(예: [{3}], 4)에서 비율 폭(1.4)이 아니라 절대 하한 2가 적용된다.
  • 가시 구간 판정 — 도메인 {70, 90} 기준: [95, 100](전부 위) → false, [60, 65](전부 아래) → false, [95, 80](일부 안) → true, [95, 60](위→아래 교차) → true, [] → false, 렌더 인덱스 밖 점만 → false.
  • 세로 막대 회귀(렌더) — 재현 조건 그대로 highlight=[{0, 75}] · goal=77 · background=[[{0,90},{1,95}], [{0,110}]]로 렌더해 배경 polyline이 0개임을 확인(막대 소멸). 본인 도트 1개와 목표선은 존재.
  • 클램프 금지 유지(#172 D3) — 가시 구간이 있는 배경 시리즈에서 범위 밖 점의 y가 밴드 밖 좌표로 남는지(클램프되지 않음) 확인.
  • 본인 0건 — highlight=[]면 svg가 없고 빈 상태 문구가 보인다. sessionLabels=[]의 기존 null 반환도 유지.
  • 본인 1건 — 도트 1개 + 목표선 1개가 모두 밴드 안에 렌더된다.
  • npm run build(tsc -b 포함) — 타입 그린. hasVisibleSegment 시그니처 변경이 다른 호출자에 없음을 컴파일러로 확인.
  • 실제 데이터 시각 확인 — 개발 서버에서 2차 미측정 + 1점 선수(드리블셔틀런)의 카드를 펼쳐 ① 좌측 세로 막대 없음 ② 도트·목표선이 카드 중앙부에 자연스럽게 배치 ③ 헤더 현재값·델타 — 그대로임을 확인.

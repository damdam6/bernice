P7 — profile-view: 종료 종목 카드 조건·미측정 가드 파생

damdam6/bernice 브랜치 feat/118-profile-view-ended-event-guards ← main 라벨 enhancement 2026-07-27

1요약

#110에서 도입된 Session.eventKeys·EventDefinition.endSessionDate 계약을 개인 프로필 파생 함수 3개(buildRadarAxes·buildGrowthCards·buildTrendSeries)에 반영한다. 레이더 축은 전역 종목이 아닌 선택 회차의 측정 종목만 남기고, 성장 카드는 종료 종목을 "그 선수 유효 기록 1건 이상"일 때만 노출하며 종료 플래그를 데이터에 얹는다(렌더는 후속 #125). 추이 차트는 이미 희소 구조를 안전하게 다루고 있음을 회귀 테스트로 고정한다. 세 함수 모두 순수 함수라 Players.tsx 호출부와 컴포넌트는 변경 없이 그대로 동작한다.

2현황 분석

src/lib/profile-view.ts의 세 함수는 #110 이전 계약(전역 events[]만 존재, endSessionDate 없음) 기준으로 작성되어 있다:

  • buildRadarAxes (src/lib/profile-view.ts:26-38) — 인자로 받은 events(목표 탭 전체, 종료 종목 포함)를 그대로 순회해 축을 만든다. session.eventKeys는 시그니처에 없고 전혀 참조하지 않는다 — 종료 종목이 있으면 그 회차에 측정되지 않았어도 값 0인 축이 계속 그려진다.
  • buildGrowthCards / GrowthCardDatum (src/lib/profile-view.ts:48-56, 86-101) — 역시 events.map(...)으로 전 종목(종료 포함)에 대해 무조건 카드를 만든다. event.endSessionDate 참조가 없고, GrowthCardDatum에 종료 여부 필드도 없다.
  • buildTrendSeries (src/lib/profile-view.ts:114-140) — trend.points(유효 기록 회차만 담는 희소 배열, shared/domain.ts:111)를 그대로 매핑하고, indexByDate.get(point.sessionDate) ?? -1 후 sessionIndex >= 0 필터(:125,128)로 알 수 없는 회차를 걸러낸다 — 구조상 이미 대부분의 미측정·종료 시나리오에 안전하다.
  • 호출부 src/pages/Players.tsx:71-72,102-106 — 여전히 전역 events를 세 함수에 그대로 넘긴다. 다만 102-104에서 cardByEvent.get(event.key)가 없으면 return null하므로, buildGrowthCards가 카드를 아예 만들지 않는 것만으로 렌더 쪽에서 자연히 숨겨진다 — 이 이슈는 Players.tsx를 건드릴 필요가 없다.
  • 디자인 PRD docs/prd-event-lifecycle.html:301-332(§08 "👤 개인 프로필")가 이 이슈의 스펙 소스: 레이더 축 가변, 성장 카드 조건부 노출 + 종료 뱃지, 추이 차트는 기존 희소 구조 유지·"별도 처리 없음"이라고 명시한다.

같은 P7 시리즈에서 이미 확립된 선례 패턴(동일 스타일을 그대로 따른다):

  • 패턴 A — functions/lib/compute-rankings.ts:71-80 (computeSessionRankings): events로 Map을 만들고 session.eventKeys를 순회 기준으로 뒤집은 뒤 eventsByKey.get(key) + undefined 필터로 역참조.
  • 패턴 C — functions/lib/player-summary.ts / shared/domain.ts:129: PlayerSummary.personalBests는 이미 "유효 기록이 1건이라도 있는 종목만"으로 스파스 필터링되어 있다 — 종료 종목의 "유효 기록 보유 여부"를 판정할 때 sessions를 다시 순회할 필요 없이 personalBests 존재 여부만 보면 된다.
  • 패턴 D — functions/lib/parse-session.ts:175-179: event.endSessionDate !== null이 종료 여부를 판정하는 원형 표현.
  • 회귀 테스트 선례 — functions/lib/compute-home-summary.test.ts:115-128, functions/lib/player-summary.test.ts:202-254: 코드 변경 없이도(또는 최소 변경으로) 종료/신규 종목 시나리오를 회귀 테스트로 고정한 전례.

3설계

  • buildRadarAxes — 순회 기준을 events에서 session?.eventKeys ?? []로 뒤집는다(패턴 A와 동형). events로 eventsByKey Map을 만들어 각 key를 역참조하고, events에 없는 key(있을 수 없지만 계약을 아직 보장 못 하는 파서를 감안해 방어적으로)는 필터링한다. session이 없으면 "선택 회차"가 없다는 뜻이므로 빈 배열을 돌려준다(현재는 session이 없어도 전역 events 개수만큼 0값 축이 그려지는데, 이는 §08이 요구하는 "축 = 선택 회차 측정 종목"과 애초에 상충하는 상태였다). 시그니처는 그대로 유지.
  • buildGrowthCards — 카드 생성 전에 events.filter(event => event.endSessionDate === null || pbByEvent.has(event.key))로 좁힌다. pbByEvent는 이미 player.personalBests(스파스)로 만들어져 있어 별도 sessions 순회 없이 "그 선수 유효 기록 1건 이상"을 그대로 판정한다(패턴 C). GrowthCardDatum에 ended: boolean 필드를 추가하고 event.endSessionDate !== null로 채운다 — 뱃지 렌더 자체는 #125 스코프이므로 GrowthStatCard.tsx는 건드리지 않는다(구조적 타이핑이라 추가 필드가 있어도 기존 소비자는 영향 없음).
  • buildTrendSeries — 코드는 변경하지 않는다. indexByDate.get(...) ?? -1 + sessionIndex >= 0 필터가 이미 "알 수 없는/제거된 회차"를 안전하게 걸러내고, trend.points가 애초에 유효 기록 회차만 담는 희소 배열이라 종료 종목은 종료 회차 이후 그냥 점이 없을 뿐 별도 처리가 필요 없다(§08 "종료 회차 이후 구간에 점이 없을 뿐 별도 처리 없음"과 정확히 일치). 이 설계 판단을 회귀 테스트로 고정해 향후 리팩토링이 이 불변식을 깨지 않도록 한다. 단, 구현 중 회귀 테스트가 실제로 깨지는 케이스를 발견하면 그 지점에서만 최소 가드를 추가한다.
  • 기각한 대안: buildGrowthCards에서 "유효 기록 보유"를 sessions를 다시 순회해 판정하는 방식 — personalBests가 이미 그 정보를 스파스하게 담고 있어 불필요한 재계산이자 새 소스(계약 밖 로직) 추가라 기각.

4작업 단계

  1. ✅ buildRadarAxes를 session.eventKeys 기준 순회(패턴 A)로 재작성 — eventsByKey Map 역참조, session 없으면 빈 배열. src/lib/profile-view.ts
  2. ✅ GrowthCardDatum에 ended: boolean 필드 추가, buildGrowthCards에 종료 종목 노출 조건(endSessionDate === null || pbByEvent.has(key)) 적용. src/lib/profile-view.ts 편차: GrowthCardDatum이 필수 필드가 되어 리터럴로 이 타입을 직접 만들던 src/components/GrowthStatCard.test.tsx의 CARD픽스처에 ended: false 한 줄을 추가(npm run typecheck가 잡아냄) — 계획엔 없던 파일이지만 타입 추가의 직접 결과라 같은 커밋 범위로 처리.
  3. ✅ buildRadarAxes 회차별 가변 축 테스트 추가 — 동일 회차에 eventKeys 4개짜리·7개짜리 두 세트를 구성해 축 개수·라벨 순서(session.eventKeys 순서, 전역 events 순서 아님)를 검증. session이 undefined일 때 빈 배열인지도 확인. src/lib/profile-view.test.ts
  4. ✅ buildGrowthCards 종료 종목 카드 노출 조건 테스트 추가 — 현역 종목은 기록 유무와 무관히 항상 노출, 종료 종목은 personalBests에 항목이 있는 선수에겐 ended: true 카드로 노출되고 없는 선수에겐 카드 자체가 배열에서 빠지는지 검증. 기존 PB·델타 테스트(profile-view.test.ts:183-225)는 무수정으로 그린 유지. src/lib/profile-view.test.ts
  5. ✅ buildTrendSeries 희소 구조 회귀 테스트 추가 — (a) 종료 종목: 종료 회차 이후 세션까지 sessions에 넘겨도 라인이 종료 회차에서 자연스럽게 끊기고 이후 구간엔 점이 생기지 않는다, (b) 중간 회차 미측정(스파스): 특정 회차만 유효 기록이 빠져도 남은 포인트의 sessionIndex가 밀리지 않고 올바른 회차에 매핑된다, (c) sessions에 없는 날짜를 가리키는 point는 무시된다(방어적 케이스). 셋 다 설계대로 코드 변경 없이 그린 — 가드 추가는 불필요했다. src/lib/profile-view.test.ts
  6. ✅ npm run test·npm run typecheck 전체 실행 — 83개 테스트 파일 710개 테스트 전부 그린, 타입체크 클린. 전체 저장소

#155버그 수정

기록지 만들기가 동작하지 않음 — 409 sheet_already_exists인데 실패 사유가 화면에 안 보이고 다음 동선도 없음

damdam6/bernice 브랜치 fix/155-create-sheet-409-dead-end ← main 라벨 bug 2026-07-28

1요약

기록지 만들기에서 create-sheet가 409로 실패해도 에러 문구가 참가자 리스트(활동 선수 ~21명) 아래 일반 플로우에 렌더돼 뷰포트 밖에 있고, 409 sheet_already_exists를 받아도 기록 입력으로 이어지는 동선이 없어 화면이 완전히 무반응처럼 보인다. 에러 표시를 스크롤과 무관하게 항상 보이는 하단 고정 바 내부로 옮기고, 409 수신 시 "오늘 기록지가 이미 있어요" 안내 + [기록 입력으로 이동] CTA(강제 새로 고침 후 이동)를 제공하며, records 캐시에 오늘 세션이 이미 있으면 사전 안내 배너를 띄운다. 같은 인라인 에러 패턴을 쓰는 AddPlayers·RecordsPlayerInput도 함께 고친다.

2현황 분석

제출 실패 흐름은 세 화면이 공유하는 src/hooks/useSubmitMutation.ts가 담당한다 — 실패 시 submitError(message 문자열)만 세우고 화면에 머문다(useSubmitMutation.ts:62-67). 세 화면 모두 이 문구를 스크롤 콘텐츠와 하단 고정 바 사이의 일반 플로우에 렌더한다:

  • src/pages/admin/CreateSheet.tsx:66-70 — 참가자 리스트 아래 <p role="alert">. 확인 바는 fixed bottom-0(CreateSheet.tsx:72)이라 항상 보이지만, 에러 문구는 문서 흐름상 리스트 끝에 있어 스크롤이 위에 있으면 뷰포트 밖.
  • src/pages/admin/AddPlayers.tsx:105-109, src/pages/admin/RecordsPlayerInput.tsx:179-183 — 동일 패턴, 동일 결함.
  • SheetManagementHome.tsx:79-83도 같은 마크업이지만 화면 콘텐츠가 짧아(버튼 4개) 스크롤 문제 없음 — 손대지 않는다.

409의 정보는 이미 계층마다 존재하지만 소비되지 않는다:

  • 서버 functions/api/admin/create-sheet.ts:51-56 — 오늘(KST) 이름의 탭이 실시트에 있으면(라이브 조회) { error: 'sheet_already_exists', message, sessionDate } 409.
  • 래퍼 src/lib/create-sheet-api.ts:54-59 — error·message는 보존하지만 409 바디의 sessionDate는 버린다.
  • 훅 useSubmitMutation.ts:26-29 — 실패에서 message만 노출. 화면은 코드 분기·CTA 없이 텍스트만 렌더.
  • 사전 감지 가능: useRecords 데이터의 sessions[].date(shared/domain.ts:68-75)와 formatSeoulDate(new Date())(src/lib/seoul-date.ts)를 비교하면 오늘 세션 존재를 렌더 시점에 알 수 있는데 CreateSheet는 players만 읽는다.

409 후 /admin/records/{date}로 그냥 이동하면 안 되는 이유: 409가 난 상황은 대개 클라이언트 records 캐시(staleTime 5분 + 엣지 캐시)가 그 탭을 모르는 상태다. RecordsParticipants.tsx:44-50은 캐시된 data.sessions에서 날짜를 못 찾으면 "회차를 찾을 수 없습니다" — 또 다른 막다른 길에 착지한다. 엣지+브라우저 캐시를 모두 뚫는 useRefreshRecords(#151, src/hooks/useRefreshRecords.ts)가 이미 있으므로 CTA에서 재사용한다.

3원인 분석

  • 가시성 결함(직접 원인) — 에러 문구가 항상 보이는 요소(fixed 바)가 아니라 스크롤 문서 흐름에 있다. 활동 선수 ~21명 리스트가 뷰포트보다 길어, 스크롤 상단에서 제출하면 문구가 화면 밖에 그려진다. 콘솔 409와 "화면 무반응"이 동시에 관찰된 것과 정확히 일치.
  • 막다른 길(설계 공백) — PRD(docs/prd-record-input.html §04)상 기록지 만들기는 "오늘 회차 탭 없으면"의 기능인데, 화면은 (a) 진입 시 오늘 세션 존재를 알리지 않고 (b) 409 후 다음 행동을 제시하지 않는다. 409 응답에 sessionDate가 있음에도 래퍼가 버리고 훅이 message만 남겨, 화면 계층에는 분기할 정보 자체가 도달하지 않는다.
  • 배제한 대안 — ① 토스트로 에러 표시: useToast는 1.9초 자동 소멸(useToast.ts:5)이라 실패 사유·CTA를 담기에 부적합, 스타일도 성공 필(다크 필) 전용. ② 409 시 자동 리다이렉트: 사용자가 원인을 모른 채 화면이 바뀌어 혼란 — 안내+명시적 CTA가 이슈의 기대 동작. ③ useSubmitMutation을 실패 객체 전체를 노출하도록 확장: 세 화면·훅 계약 전부에 파급 — CreateSheet의 thunk에서 결과를 관찰해 로컬 상태로 남기는 편이 국소적이고 계약 변경이 없다.

4작업 단계

  2. CreateSheet: submitError 렌더를 하단 고정 바 컨테이너 내부(버튼 위)로 이동 — 스크롤과 무관하게 항상 보인다. src/pages/admin/CreateSheet.tsx ✅ 완료 — conflict 분기와 함께 바 내부로 이동
  3. CreateSheet 409 분기: handleConfirm의 thunk에서 결과를 관찰해 error === 'sheet_already_exists'면 conflictDate 상태를 세운다(result.sessionDate ?? formatSeoulDate(new Date()), 제출 시작 시 해제). conflict 시 하단 바에 "오늘 기록지가 이미 있어요" 안내(role=alert)를 띄우고 기본 버튼을 [기록 입력으로 이동]으로 교체. CTA는 useRefreshRecords.refresh() 성공 후 /admin/records/{conflictDate}로 navigate — 실패하면 이동하지 않고 실패 메시지를 같은 자리에 보여 재시도 가능하게 한다(스테일 캐시로 "회차를 찾을 수 없습니다"에 착지하는 2차 막다른 길 방지). src/pages/admin/CreateSheet.tsx ✅ 완료 — refresh 실패 시 미이동·문구 표시·재시도 유지
  4. CreateSheet 사전 안내: data.sessions에 formatSeoulDate(new Date())와 같은 날짜가 있으면 헤더 아래 안내 배너("오늘 기록지가 이미 있어요") + [기록 입력으로 이동](캐시에 세션이 있으므로 바로 navigate)을 렌더. 만들기 플로우는 차단하지 않는다 — 스테일 캐시 가능성이 있어 보조 수단이고, 최종 커버는 409 처리(이슈 완료 조건 명시). src/pages/admin/CreateSheet.tsx ✅ 완료 — 헤더 아래 카드 배너, 플로우 비차단
  5. 동일 가시성 결함 수정: AddPlayers·RecordsPlayerInput의 submitError도 각자 하단 고정 바 내부로 이동. src/pages/admin/AddPlayers.tsx, src/pages/admin/RecordsPlayerInput.tsx ✅ 완료
  6. 테스트: ① 래퍼 — 실패 시 sessionDate 패스스루/부재 케이스. ② CreateSheet — 409 → 안내+CTA 노출·기존 화면 유지, CTA 클릭 → /api/refresh 호출 후 참가자 목록 스텁 착지, refresh 실패 → 이동 없이 실패 문구, 오늘 세션 포함 데이터 → 사전 배너, alert가 fixed 컨테이너 내부에 렌더되는지(placement 어서션). ③ AddPlayers·RecordsPlayerInput — 기존 실패 테스트에 placement 어서션 추가. src/lib/create-sheet-api.test.ts, src/pages/admin/CreateSheet.test.tsx, src/pages/admin/AddPlayers.test.tsx, src/pages/admin/RecordsPlayerInput.test.tsx ✅ 완료 — 대상 4파일 35개 + 전체 784 테스트·tsc 그린

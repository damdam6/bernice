P7 — parse-goals 5열 스키마: 종료 회차 파싱·V5 검증·행 번호 동반

damdam6/bernice 브랜치 feat/111-parse-goals-5col-schema ← main 라벨 enhancement 2026-07-27

1요약

목표 탭 파서(functions/lib/parse-goals.ts)가 아직 4열(종목·목표·만점·방향)만 읽고, E열(종료 회차)은 #110에서 도메인 타입에만 추가된 채 하드코딩 null로 방치돼 있다. 이 이슈는 헤더를 5열로 엄격화하고, E열 값을 빈칸/- → null(현역), 그 외에는 YYYY-MM-DD + 캘린더 유효(isValidRoundTabName 재사용, V5)로 파싱해 endSessionDate에 채운다. 형식 오류는 기존 fail() 관례(행 번호·종목명)로 즉시 throw한다. 동시에 각 종목의 목표 탭 실제 행 번호를 파서 반환값에 내부적으로 동반시켜(#121 create-sheet가 나중에 쓸 참조 수식용) — RecordsResponse 공개 계약에는 노출하지 않는다.

2현황 분석

functions/lib/parse-goals.ts:14의 EXPECTED_HEADER = ['종목', '목표', '만점', '방향']는 4열만 검증한다. validateHeader(:43-49)는 EXPECTED_HEADER.every((expected, i) => cells[i] === expected) — 자기 배열 길이만큼만 위치 비교한다.

parseGoalRow(:51-72)는 row[0](종목명)·row[1](목표치)·row[2](만점, parseMaxScore)·row[3](방향, parseDirection)만 읽고, :70에서 endSessionDate: null, // 5열(종료 회차) 파싱은 별도 이슈 — 이 파서는 아직 4열만 읽는다로 하드코딩돼 있다. row[4]는 전혀 참조되지 않는다.

parseMaxScore(:74-79)는 MAX_SCORE_NULL_LITERALS = new Set(['', '-'])(:15)로 "빈칸 또는 - = null" 관례를 이미 구현해 뒀다 — PRD D1이 종료 회차에도 그대로 재사용하라고 명시한 그 관례다.

회차 탭 이름 형식·캘린더 검증은 functions/lib/sheetTabs.ts:56-58의 isValidRoundTabName(name)이 이미 구현해 뒀다 — 정규식 /^(\d{4})-(\d{2})-(\d{2})$/ 매치 후 Date.UTC 왕복 검증으로 2025-02-30 같은 캘린더 무효 날짜를 걸러낸다. functions/api/admin/records.ts:56에서 이미 같은 방식으로 재사용 중이다.

fail-loud 에러 헬퍼는 이미 fail(sheetRow, name, reason)(parse-goals.ts:88-90) 하나로 통일돼 있다 — 목표 탭 파싱 실패 ({sheetRow}행 "{name}"): {reason}. parseMaxScore·parseDirection이 이 헬퍼를 그대로 호출하는 것과 동일한 패턴을 새 E열 검증에도 쓰면 된다.

중복 검사(:31-35)는 이미 firstSeenRowByKey = new Map<string, number>()(:23)로 "종목 key → 첫 등장 시트 행 번호"를 추적하고 있다 — 이 이슈가 요구하는 "행 번호 동반"과 정확히 같은 모양의 데이터라, 새로 만들 필요 없이 이 맵을 반환값으로 승격하면 된다.

parseGoals의 반환값(현재 EventDefinition[])은 3곳에서 그대로 소비된다: functions/lib/build-records-response.ts:49(→ RecordsResponse.events로 직결, shared/domain.ts:150), functions/api/admin/create-sheet.ts:71, functions/api/admin/records.ts:71(integrity()로 감싼 호출). 셋 다 반환값을 EventDefinition[] 그대로 하류에 넘기므로, 반환 타입이 바뀌면 세 곳 모두 한 줄씩 구조분해가 필요하다.

EventDefinition.endSessionDate: string | null은 #110(커밋 ecb4084)에서 이미 shared/domain.ts:38-48에 추가됐고, 프론트 런타임 검증(src/lib/parse-records-response.ts:64,72)도 이미 이 필드를 검증·조립한다 — 즉 공개 계약 배선은 끝나 있고, 이 이슈는 오직 parseGoals가 실제 값을 채우게 만드는 것만 남았다.

테스트 픽스처 4곳이 4열 목표 탭 배열을 하드코딩하고 있어, 헤더를 5열 엄격 검증으로 바꾸면 그대로 깨진다: functions/api/records.test.ts:26-27, functions/lib/build-records-response.test.ts:13-14, functions/api/admin/create-sheet.test.ts:33-35, functions/api/admin/records.test.ts:34-38. (functions/lib/sheetsApi.test.ts:288,300도 같은 모양이지만 fetchSheetBundle은 parseGoals를 호출하지 않으므로 영향 없음 — 안 건드림.)

스코프 확정: gh issue list로 확인한 결과 이 PRD(docs/prd-event-lifecycle.html)의 "이슈 2"(§13, parse-goals+parse-session 묶음)는 실제로는 두 이슈로 쪼개져 있다 — #111(이 이슈, parse-goals E열·V5·행 번호만)과 #112(parse-session의 mapHeaderToEvents V3 완화·V4 신설·eventKeys). V6(종료 회차 ↔ 실존 회차 탭 대조, §04·§05)는 build-records-response.ts가 담당하는 #120 소관이고, 실제 행 번호를 참조 수식에 쓰는 것은 #121 소관이다. 이 계획은 GitHub 이슈 본문을 기준으로 parse-goals 파일 하나(+ 그 호출부 시그니처 정합)로 범위를 좁힌다.

3설계

  • 헤더 검증: EXPECTED_HEADER에 '종료 회차'를 5번째로 추가하기만 하면 된다 — validateHeader의 기존 위치별 비교 로직은 그대로 두면 4열짜리 구 헤더가 자동으로 cells[4] === undefined !== '종료 회차'로 걸려 에러가 난다(요구사항 "4열 구 헤더는 에러" 자동 충족). 길이 자체를 별도로 체크하는 로직은 추가하지 않는다 — 기존 파일의 "위치별 비교" 스타일과 일관되고, PRD 검증 매트릭스(V1~V6)에 "6번째 이상 컬럼" 케이스가 없어 과잉 방어가 된다.
  • 널 리터럴 상수 공유: MAX_SCORE_NULL_LITERALS를 NULL_LITERALS로 이름을 일반화해 parseMaxScore와 신설 parseEndSessionDate가 함께 쓴다 — 만점 열과 종료 회차 열이 "빈칸 또는 - = null"이라는 같은 관례를 쓴다는 shared/domain.ts:45-47의 주석(D1)과 일치시키는 이름이다.
  • E열 파싱 함수: parseMaxScore/parseDirection과 같은 시그니처 모양으로 parseEndSessionDate(raw, sheetRow, name): string | null을 추가한다 — trim().normalize('NFKC') 후 NULL_LITERALS면 null, 아니면 isValidRoundTabName()으로 형식+캘린더 검증하고 실패 시 fail()로 행 번호·종목명 포함 에러. isValidRoundTabName 내부가 다시 NFC 정규화를 하므로 이중 정규화 걱정은 없다(NFKC 출력은 이미 NFC 상태).
  • 실존 회차 대조(V6) 미포함: 종료 회차 날짜가 실제 회차 탭 목록에 있는지 대조하는 것은 의도적으로 이 파서에 넣지 않는다 — parseGoals는 회차 탭 목록을 모르고(PRD §04 "대조는 조립 단계가 수행"), 그 책임은 #120의 build-records-response.ts다.
  • 행 번호 동반 방식: 새 병렬 구조체를 만들지 않고, 기존 firstSeenRowByKey 맵을 sheetRowByKey로 이름만 바꿔 반환값에 그대로 승격한다 — 이미 "종목 key → 그 종목이 처음(=유일하게, 중복이면 에러니까) 등장한 시트 행"을 정확히 담고 있는 자료구조라 중복 로직이 필요 없다. 반환 타입은 { events: EventDefinition[]; sheetRowByKey: Map<string, number> } — 코드베이스의 기존 "byKey" 관례(parse-session.ts의 eventByKey, buildPlayersByName)와 동일하게 Map을 쓴다. 대안으로 고려한 "튜플 배열({event, sheetRow}[])"은 소비자가 다시 key로 찾아야 해서 #121이 쓰기 불편해 기각.
  • 호출부 정합: 3개 호출부는 로직 변경 없이 const events = parseGoals(...) → const { events } = parseGoals(...)로만 바꾼다 — sheetRowByKey는 지금 아무도 쓰지 않으므로(그 소비자는 #121) 구조분해에서 그냥 무시한다.

4작업 단계

  1. 목표 탭 파일 docblock(:1-9)과 EXPECTED_HEADER(:14)를 5열(['종목', '목표', '만점', '방향', '종료 회차'])로 갱신 — 열 순서 주석도 함께 고친다. functions/lib/parse-goals.ts
  2. MAX_SCORE_NULL_LITERALS를 NULL_LITERALS로 리네임(만점·종료 회차 공용 상수라는 주석 추가)하고, parseMaxScore의 참조를 갱신한다. functions/lib/parse-goals.ts
  3. isValidRoundTabName을 ./sheetTabs에서 import하고, parseDirection 바로 아래에 parseEndSessionDate(raw, sheetRow, name): string | null을 추가한다 — NULL_LITERALS 체크 → isValidRoundTabName 형식+캘린더 검증 → 실패 시 fail(sheetRow, name, "종료 회차 형식이 올바르지 않음 (...)：\"${raw}\""). functions/lib/parse-goals.ts
  4. parseGoalRow의 반환 객체에서 endSessionDate: null, // 5열... 줄을 endSessionDate: parseEndSessionDate(row[4] ?? '', sheetRow, name)로 교체한다. functions/lib/parse-goals.ts
  5. parseGoals 본체를 개정한다: 로컬 변수 firstSeenRowByKey를 sheetRowByKey로 이름 바꾸고, 함수 반환 타입을 새 export interface ParseGoalsResult { events: EventDefinition[]; sheetRowByKey: Map<string, number> }로 바꿔 { events, sheetRowByKey }를 반환한다(빈 배열 조기 리턴 :19 포함, { events: [], sheetRowByKey: new Map() }). functions/lib/parse-goals.ts
  6. 3개 호출부를 구조분해로 갱신한다 — 로직 변경 없음, 반환 타입 변경에 맞춘 한 줄 수정. functions/lib/build-records-response.ts:49, functions/api/admin/create-sheet.ts:71, functions/api/admin/records.ts:71
  7. 4개 테스트 픽스처 파일의 목표 탭 헤더에 5번째 열('종료 회차')을 추가해 5열 헤더 검증을 통과하도록 맞춘다. functions/api/records.test.ts:26-27, functions/lib/build-records-response.test.ts:13-14, functions/api/admin/create-sheet.test.ts:33-35, functions/api/admin/records.test.ts:34-38 계획과 한 가지 다름: 데이터 행에는 5번째 셀을 굳이 추가하지 않고 헤더만 5열로 맞췄다 — row[4] ?? ''가 이미 "생략된 trailing 셀 = 빈칸"을 처리하므로 결과는 동일하고, 실제 Sheets API가 각 행 끝의 빈 셀을 잘라 돌려주는 동작을 그대로 재현한다.
  8. parse-goals.test.ts의 HEADER·SAMPLE_ROWS를 5열로 갱신하고, 반환값 구조분해(const { events } = parseGoals(...))에 맞춰 기존 toEqual 어서션을 조정한다. functions/lib/parse-goals.test.ts
  9. 새 테스트를 추가한다: (a) E열 빈칸/-/trailing 셀 생략 → null, (b) 정상 YYYY-MM-DD → 그대로 endSessionDate, (c) 형식 오류(날짜 아님) → /{row}행 "{종목}"/ 매치 에러, (d) 캘린더 무효 날짜(2025-02-30) → 에러, (e) 4열 구 헤더 → "헤더가 예상과 다릅니다" 에러, (f) sheetRowByKey가 각 종목 key → 실제 시트 행을 정확히 담는지, 중간 공백 행이 있어도 이후 행 번호가 밀리지 않는지. functions/lib/parse-goals.test.ts

리스크영향완화책

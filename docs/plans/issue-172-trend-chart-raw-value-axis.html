종목 추이 차트 Y축을 정규화 성능 → 원값으로 전환 — 시간 종목의 "값은 늘었는데 선이 떨어지는" 반직관 해소

damdam6/bernice 브랜치 feat/172-trend-chart-raw-value-axis ← main 라벨 enhancement 2026-07-30

1요약

개인 프로필 성장 카드의 확장 추이 차트만 정규화 성능(0~1) 공간에서 원값 공간으로 옮긴다. 점의 y는 종목 원값(시간=초, 개수=개)이고 축은 반전하지 않아 값이 크면 항상 위 — 즉 시간 종목은 기록이 늘면 선이 올라가고, 좋고 나쁨은 카드 헤더의 델타 색과 목표선이 전달한다(D1). 축 범위는 본인 recorded 점 ∪ 목표값 + 패딩이며 팀 배경 라인은 범위 계산에서 빠지고 범위를 벗어난 구간은 클립된다(D3). 축 눈금·값 라벨은 계속 없다(D2). performance-scale.ts는 레이더·랭킹 바 전용으로 한 줄도 건드리지 않는다.

2현황 분석

추이 차트는 데이터 결합 → 좌표 계산 → 렌더의 3층이고, 세 층 모두 "정규화 성능 0~1"을 전제로 쓰여 있다.

  • 결합 — src/pages/Players.tsx:58이 buildPerformanceScale(events, sessions) 인스턴스 하나를 만들어 레이더·추이가 공유하고(§07), src/pages/Players.tsx:106이 확장된 카드에 대해서만 buildTrendSeries(event, sessions, players, player.id, scale)를 호출한다.
  • src/lib/profile-view.ts:134-151 — 각 점을 scale.normalize(event.key, point.value)로 0~1로 바꾸고, 목표선도 scale.normalize(event.key, event.targetValue)로 같은 공간에 넣는다. TrendSeries.goal은 "정규화 목표선 0~1"로 문서화돼 있다(src/lib/profile-view.ts:115-122).
  • 좌표 — src/components/charts/trend-math.ts:31-34의 trendY(value, layout)가 clamp01(value) 후 1 - value로 반전한다("위가 좋음"). TrendPointDatum.value 주석도 "정규화 성능 0~1"(src/components/charts/trend-math.ts:16).
  • 렌더 — src/components/charts/trend-chart.tsx:40이 trendY(clamp01(goal), layout)로 목표선 y를 잡고, 배경(primary-soft 1.6px) → 목표선(good 1.5px 점선) → 본인 라인(primary 3.2px) → 도트(r3.6) → x축 회차 라벨 순서로 그린다(src/components/charts/trend-chart.tsx:44-94). 축 눈금·값 라벨은 원래 없다.

반직관의 출처는 정규화 함수 자체다. src/lib/performance-scale.ts:73-76은 만점 없는 종목(시간 종목 전부)을 전 회차·전 선수 recorded의 min~max 상대 스케일로 깔고, direction === '낮을수록'이면 1 - ratio로 뒤집는다. 그래서

  • 기록이 1:16 → 13:22로 늘어나면 정규화 값은 떨어지고, 반전까지 겹쳐 선이 내려간다 — 축 라벨도 값 표기도 없으니 읽을 방법이 없다.
  • 스케일 분모가 전 선수 공통이라 타인의 극단값 1건(13:22 오입력)이 본인 과거 점의 y까지 재배치한다(src/lib/performance-scale.ts:41-55의 ranges 집계 범위).

영향 범위는 좁다. performance-scale의 다른 소비자는 레이더(src/components/charts/radar-chart.tsx, buildRadarAxes)와 랭킹 미니바(src/components/charts/performance-bar.tsx)뿐이고 둘 다 정규화를 유지한다(이슈의 전 차트 점검 결과). src/pages/Players.test.tsx:190-239는 추이 차트를 aria-label 존재로만 검증하므로 값 변경에 영향받지 않는다. 좌표·렌더 테스트는 src/components/charts/trend-math.test.ts·src/components/charts/trend-chart.test.tsx가 0~1 값을 하드코딩하고 있어 이번에 갱신 대상이다.

3설계

확정 결정 D1~D3을 코드로 옮기는 설계다. 핵심은 축 도메인이라는 개념을 새로 도입하고, y 매핑에서 반전과 클램프를 동시에 제거하는 것.

D1 · 원값 축, 반전 없음

  • trendY(value, domain, layout)로 서명을 바꾸고 y = padTop + (1 - (value - domain.min) / (domain.max - domain.min)) * inner로 선형 매핑한다. 값이 크면 위 — 수학 좌표 그대로다.
  • 결과적으로 direction 분기 코드가 한 줄도 없다: 낮을수록 종목은 개선(값 감소) 시 자연히 하강하고, 높을수록 종목은 개선 시 상승한다. "방향 필드 기반 · 종목 하드코딩 금지"를 분기로 만족시키는 게 아니라 분기를 없애서 만족시킨다 — 종목명이 코드에 등장할 여지가 원천 차단된다.
  • 좋고 나쁨은 기존 경로가 이미 담당한다: 카드 헤더 델타의 ▲▼·색은 src/lib/profile-view.ts의 buildDelta가 계약의 improved(상류에서 direction 반영)로 계산하고, 목표선은 원값 위치에 그려진다.

D3 · 도메인 = 본인 recorded ∪ 목표 + 패딩

  • trend-math.ts에 순수 함수 trendDomain(highlight, goal, background?)와 TrendDomain {min, max}를 추가한다. DOM 없이 단위 테스트한다는 이 파일의 기존 원칙(파일 헤더 주석) 그대로.
  • 범위는 본인 점 ∪ 목표값으로만 잡고 배경은 제외 → 목표선은 항상 밴드 안에 보인다.
  • 패딩은 span의 8%를 위아래로. min === max(본인 점 1개 또는 전부 동률, 목표까지 같은 값)면 ±max(|v| × 0.1, 1)로 잡아 점이 중앙에 오는 폴백.
  • 본인 점도 목표도 없는 degenerate 케이스(prop 수준에서만 가능)에서는 배경 extent로 폴백하고, 그것도 없으면 0~1 — 차트가 통째로 빈 화면이 되는 것만 막는 최후 방어선이다.
  • 클립: 배경 폴리라인을 <g clip-path>로 감싸고 <clipPath><rect>를 플롯 밴드(padX … width-padX × padTop … height-padBottom)에 맞춘다. 값 왜곡을 낳는 가장자리 클램프는 쓰지 않는다(trendY에서 clamp01 제거가 곧 이 조건). id는 useId()로 인스턴스 고유하게 만들어 같은 페이지 다중 차트에서 충돌하지 않게 한다.
  • 본인 라인·도트와 x축 라벨은 클립하지 않는다: 본인 점은 도메인상 항상 밴드 안이고, r3.6 도트가 밴드 경계에서 반쪽만 그려지는 부작용을 피한다. x 라벨은 애초에 밴드 밖(height - 8)이다.

D2 · 축 눈금·값 라벨 없음

현행 그대로 x축 회차 라벨만 유지한다 — 추가 텍스트 요소를 넣지 않는 것이 작업 내용이다. 수치는 카드 헤더(현재값·PB·델타)가 담당.

경계면 정리

  • buildTrendSeries는 scale 파라미터를 제거한다 — 값이 원값이 되면 쓰이지 않고, noUnusedParameters: true(tsconfig.app.json:19)라 남겨둘 수도 없다. Players.tsx의 scale은 레이더용으로 계속 필요하다.
  • src/lib/performance-scale.ts는 무변경. 단, 파일 헤더의 "레이더·종목 추이·랭킹 미니바가 공유" 서술은 사실과 달라지므로 주석만 정정한다(동작 변경 없음).
  • trend-chart.tsx·trend-math.ts의 clamp01 import는 제거된다(noUnusedLocals).
  • docs/prd-design.html의 §05 확장 추이 차트 행(:205)·§07 차트 표(:259)·정규화 콜아웃(:263)에 "추이 차트만 원값 축(#172)" 예외를 기록한다 — 이슈가 명시한 PRD 개정.
  • #171(섹션 범례)은 아직 코드가 없다(PR 없음). 범례는 "연보라 = 다른 선수"를 설명하므로 축 전환과 무관하게 유효 — 이번 변경에서 문구 충돌이 생기지 않는지 확인만 하고 코드는 손대지 않는다.

기각한 대안

  • 낮을수록 종목에서 축 반전(위 = 좋음 유지) — D1이 명시적으로 금지. 종목마다 "위"의 의미가 뒤집혀 배경 라인·목표선 해석이 더 어려워진다.
  • 배경 라인을 축 가장자리로 클램프 — D3가 금지. 실제로 없는 값처럼 보이는 왜곡을 만든다.
  • 도메인을 buildTrendSeries에서 계산해 prop으로 넘기기 — 도메인 입력(본인 점·목표)이 이미 차트 props에 전부 있어 중복 전달이 된다. 축 규칙은 "어떻게 그리는가"이므로 차트 쪽(trend-math)이 소유하는 편이 응집도가 높고, 순수 함수라 테스트 비용도 같다.
  • 공유 scale에 "원값 통과" 모드를 추가 — 레이더·랭킹과 공유하는 함수에 분기를 심는 셈이라 §07 "같은 함수를 공유해 값이 정의상 일치" 계약을 흐린다. 추이만 scale에서 빠지는 게 정확한 표현.

5리스크

리스크영향완화책
도메인이 목표값을 항상 포함 — 목표가 극단이면 본인 점들이 좁은 띠로 눌린다추이 모양 가독성 저하D3 확정 사항으로 수용. 목표는 목표 탭에서 관리되는 값이라 회차 기록 오입력과 유입 경로가 다르다
본인 범위가 좁으면 배경 라인이 거의 다 클립되어 사라져 보인다팀 비교 맥락 상실의도된 동작("자신의 추이만 보는" 차트). 배경의 의미는 #171 범례가 설명하고, 팀 비교는 랭킹 화면이 담당
clipPath id 충돌 — 한 페이지에 추이 차트가 둘 이상 렌더될 때엉뚱한 영역으로 클립useId()로 인스턴스 고유 id 생성. 현재 화면은 한 번에 한 카드만 확장하지만 방어적으로 적용
시간 종목에서 "선이 내려가면 개선"이 처음엔 낯설다사용자 재학습 비용D1의 명시적 결정. 판정은 헤더 델타 ▲▼ 색과 목표선이 전달하고, 축은 "값의 크기"만 표현한다
정규화 함수에서 추이가 빠지며 레이더·랭킹 회귀 우려세 차트 값 정의 불일치performance-scale.ts 로직 무변경 + 기존 performance-scale.test.ts·레이더·랭킹 바 테스트를 손대지 않고 통과시켜 확인
trendY·buildTrendSeries 서명 변경이 다른 호출부를 깬다타입 에러호출부는 trend-chart.tsx·Players.tsx와 각 테스트로 한정됨을 grep으로 확인. npm run typecheck가 잔여 호출부를 잡는다

6테스트 계획

  • npm run typecheck · npm test — 전체 green (변경 파일 외 회귀 없음)
  • trend-math — trendY가 도메인 min을 하단(height - padBottom), max를 상단(padTop)에 놓고 중간값은 선형 보간. 도메인 밖 값은 클램프되지 않고 밴드 밖 좌표를 낸다(클립 전제)
  • trend-math — trendDomain: 본인 점 min~max에 8% 패딩, 목표값이 본인 범위 밖이면 도메인이 목표까지 확장, 배경 점은 도메인에 영향 없음, 본인 점 1개/전부 동률이면 min < v < max인 중앙 배치 폴백, 본인·목표 모두 없으면 배경 extent 폴백
  • trend-chart(방향) — 높을수록 종목 값 [6, 8](개선 = 증가)은 뒤 점의 y가 더 작다(상승), 낮을수록 종목 값 [90, 76](개선 = 감소)은 뒤 점의 y가 더 크다(하강). 두 케이스가 같은 코드 경로를 타고 direction 인자가 아예 없음을 함께 확인
  • trend-chart(클립) — 배경 polyline을 감싼 g가 clip-path="url(#…)"를 갖고, clipPath > rect가 플롯 밴드(x=padX, y=padTop, width=W-2·padX, height=H-padTop-padBottom)와 일치. 본인 polyline·circle·text는 그 그룹 밖
  • trend-chart(목표선) — 목표가 본인 점 범위 밖(위·아래 양쪽)이어도 목표선 y가 [padTop, height - padBottom] 안에 있다
  • trend-chart(기존 유지) — 배경(1.6px primary-soft)이 본인 라인(3.2px primary)보다 먼저, 도트 r3.6, 목표선 good 1.5px 점선(4 4), x축 회차 라벨, aria-label, 회차 0개면 렌더 없음
  • profile-view — buildTrendSeries의 highlight·background 값이 원값(예: 셔틀런 90·100초, 골밑슛 6·8개), goal === event.targetValue, 희소 회차·종료 종목·본인 부재·빈 배경 제외 케이스는 기존 그대로
  • 미측정·면제 희소 점 — 계약상 trends[].points[]에 유효 기록만 담기므로 처리 규칙 무변경. 중간 회차 결손 시 sessionIndex가 밀리지 않는 기존 테스트로 재확인
  • 정규화 회귀 — performance-scale.test.ts, radar-chart.test.tsx, radar-math.test.ts, performance-bar.test.tsx, achievement-gauge.test.tsx, Players.test.tsx를 수정 없이 통과

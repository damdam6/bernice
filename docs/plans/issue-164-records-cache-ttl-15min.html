records 엣지 캐시 TTL 6시간→15분 — 콜로 로컬 스테일 상한 축소

damdam6/bernice 브랜치 feat/164-records-cache-ttl-15min ← main 라벨 enhancement 2026-07-28

1요약

Cloudflare Cache API의 cache.delete는 콜로(데이터센터) 로컬이라, 쓰기 무효화가 닿지 않은 콜로에 붙은 팀원은 엣지 저장 사본의 TTL이 지나야 새 데이터를 본다. 현재 RECORDS_CACHE_TTL_SECONDS가 6시간이라 최악의 경우 6시간 스테일이 발생할 수 있다. TTL을 15분으로 낮춰 이 구조적 한계의 피해 상한을 축소한다. Sheets API 부하 증가분은 콜로당 15분에 한 번(2콜)이라 무시 가능한 수준이다.

2현황 분석

  • functions/api/records.ts:19-20 — caches.default.match로 콜로 로컬 저장 사본을 조회, 히트하면 그대로 반환.
  • functions/api/records.ts:22-34 — 미스 시 Sheets API로 재조립하고, 응답에 Cache-Control: public, max-age=RECORDS_CACHE_TTL_SECONDS를 실어 context.waitUntil(cache.put(...))로 엣지에 저장(#162 이후: 클라이언트로 나가는 사본은 withNoStore로 별도 처리, 저장 사본만 max-age 유지).
  • functions/lib/records-cache.ts:13 — RECORDS_CACHE_TTL_SECONDS = 60 * 60 * 6(6시간), 주석은 "긴 캐시" 기본값이라 명시.
  • functions/lib/records-cache.ts:17-19 — purgeRecordsCache()가 무효화 단일 창구. admin/records.ts·add-players.ts·create-sheet.ts·refresh.ts 등 쓰기 경로가 모두 이걸 거치지만, cache.delete 자체가 콜로 로컬이라 다른 콜로의 저장 사본은 지워지지 않고 TTL까지 산다(Cloudflare 공식 제약, 코드로 우회 불가).
  • docs/prd-record-input.html:375 — §09 "알려진 한계" callout이 "다른 콜로에 남은 캐시는 TTL(6시간)까지 살 수 있다"고 명시. 상수를 바꾸면 이 문구도 실제와 어긋난다.
  • functions/api/records.test.ts:83 — 저장 사본 Cache-Control 어서션이 `public, max-age=${RECORDS_CACHE_TTL_SECONDS}`로 상수를 직접 참조(하드코딩된 숫자 아님) → 상수만 바꾸면 테스트는 자동으로 새 값을 기대하게 되어 별도 수정 불필요, 실행으로만 확인.

3설계

선택한 설계: RECORDS_CACHE_TTL_SECONDS 상수 값만 60 * 60 * 6 → 60 * 15로 축소하고, 주석을 "긴 캐시 기본값"에서 "콜로 로컬 한계의 안전망 TTL"로 갱신한다. 무효화 로직·캐시 키·호출부는 전혀 건드리지 않는다 — 이 이슈는 상수 하나와 그 상수를 설명하는 문서 두 곳의 정합성 문제다.

기각한 대안 — 엣지 저장 사본도 no-store로: #162에서 이미 브라우저 응답은 no-store로 분리했다. 저장 사본까지 no-store로 만들면 캐시가 아예 무력화되어 모든 /api/records 요청마다 Sheets API를 호출하게 된다 → 부하가 무시 가능한 수준을 훨씬 넘어서 기각.

기각한 대안 — TTL을 0에 가깝게(예: 1분): 콜로당 재조립 빈도가 커져 Sheets API rate limit에 더 가까워진다. 이슈의 완료 조건이 명시한 15분(콜로당 15분 1회, 2콜)이 "무시 가능한 부하"와 "합리적 스테일 상한"의 균형점이므로 그대로 채택.

4작업 단계

  1. 스텝 1: RECORDS_CACHE_TTL_SECONDS를 60 * 60 * 6 → 60 * 15로 변경하고, 바로 위 주석을 "긴 캐시 기본값"에서 콜로 로컬 한계의 안전망 TTL이라는 취지로 갱신 functions/lib/records-cache.ts:11-13
  2. 스텝 2: §09 콜로 callout의 "TTL(6시간)까지 살 수 있다" 문구를 "TTL(15분)까지 살 수 있다"로 갱신 docs/prd-record-input.html:375
  3. 스텝 3: vitest run functions/api/records.test.ts로 TTL 관련 어서션(records.test.ts:83) 영향 확인 — 상수 참조 방식이라 무변경으로 통과할 것으로 예상, 실제 실행으로 검증 functions/api/records.test.ts 확인 완료: 어서션 무변경, `vitest run functions/api/records.test.ts` 5개 테스트 통과 · 전체 `vitest run` 797개 통과 · `tsc -b` 클린

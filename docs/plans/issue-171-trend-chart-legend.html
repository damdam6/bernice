#171기능 개선

프로필 추이 차트에 범례가 없어 연보라 배경 라인의 의미를 알 수 없음 — '종목별 성장' 섹션 헤더의 PB 설명 옆 소형 범례 추가

damdam6/bernice 브랜치 feat/171-trend-chart-legend ← main 라벨 enhancement 2026-08-02

1요약

확장 추이 차트는 팀원 배경 라인(primary-soft)·본인 하이라이트(primary)·목표선(good 점선) 세 마크를 축 라벨 없이 겹쳐 그리는데, 화면 어디에도 이를 설명하는 텍스트가 없어 연보라 선의 의미가 전달되지 않는다. 차트와 동일한 Tailwind 색 클래스를 쓰는 소형 SVG 범례 컴포넌트(TrendLegend)를 charts/ 폴더에 새로 만들고, '종목별 성장' 섹션 헤더의 PB 설명 옆에 wrap 허용 그룹으로 붙여 카드 확장 여부와 무관하게 상시 노출한다.

2현황 분석

개인 프로필의 확장 추이 차트는 세 종류의 마크를 겹쳐 그린다. src/components/charts/trend-chart.tsx 기준:

  • 팀원 배경 라인 — trend-chart.tsx:70-77, polyline + className="stroke-primary-soft" + strokeWidth={1.6}. 본인을 제외한 전 선수의 추이가 여러 줄 깔린다.
  • 목표선 — trend-chart.tsx:80-90, line + className="stroke-good" + strokeWidth={1.5} + strokeDasharray="4 4".
  • 본인 하이라이트 — trend-chart.tsx:91-99(polyline, stroke-primary, 3.2px)와 trend-chart.tsx:100-109(circle, fill-primary, r 3.6).

차트에는 축 눈금도 값 라벨도 없다(수치는 카드 헤더가 담당) — 즉 화면 안에 이 세 마크를 설명하는 텍스트가 단 하나도 없다. 사용자가 연보라 선을 "내 다른 종목인가?"로 오해할 여지가 그대로 남는다.

현재 섹션 헤더는 src/pages/Players.tsx:96-99 한 줄뿐이다:

  • <div className="mt-1 flex items-center justify-between px-0.5"> 안에 좌측 <h2 className="text-sm font-bold text-ink">종목별 성장</h2>, 우측 <span className="text-xs text-ink-sub">PB : Personal Best</span>.
  • 이 헤더는 카드 확장 상태와 무관하게 항상 렌더된다 — 이슈가 요구하는 "상시 노출" 자리로 이미 적합하다.

토큰 실측값(src/index.css): --color-primary #3f51b5 · --color-primary-soft #c5cae9 · --color-good #3f9e6b. 디자인 PRD docs/prd-design.html:205,259의 차트 스펙과 일치하며, 범례는 이 동일한 Tailwind 클래스를 재사용해야 색이 갈라지지 않는다.

기존 범례 컴포넌트는 레포에 없다(src/ 전역 검색 결과 0건). docs/plans/issue-172-*.html·issue-174-*.html이 "#171 범례가 배경 라인의 의미를 설명한다"를 전제로 남겨둔 상태라, 이번 작업이 그 공백을 메운다.

3설계

컴포넌트 위치 — src/components/charts/trend-legend.tsx. 범례가 설명하는 대상이 TrendChart의 세 마크이므로 차트 폴더에 같이 두고 charts/index.ts로 내보낸다. 폴더 관례(kebab-case 파일 / PascalCase export, 예: achievement-gauge.tsx → AchievementGauge)를 그대로 따른다. 화면 전용 조각으로 Players.tsx에 인라인하지 않는 이유는, 마커 색·굵기·점선이 차트 렌더와 한 몸으로 바뀌어야 하는 값이기 때문이다 — 같은 폴더에 있어야 한쪽만 바뀌는 사고를 막는다.

마커는 텍스트 글리프가 아니라 SVG. ●는 무난하지만 점선 글리프(┅ U+2505)는 Pretendard 폴백에 따라 깨질 수 있고, 굵기·점선 간격을 차트와 맞출 수단이 없다. 각 항목을 14×8 viewBox의 소형 SVG로 그리고 차트와 완전히 같은 클래스를 쓴다:

  • 본인 — line stroke-primary (2.4px) + circle fill-primary (r 2.4) → 차트의 "굵은 선 + 도트"를 축소 재현
  • 팀원 — line stroke-primary-soft (1.6px) → 차트 배경 라인과 굵기까지 동일
  • 목표 — line stroke-good (1.5px) + strokeDasharray="3 2" → 14px 폭에서 점선이 최소 3칸 보이도록 4 4 대신 3 2로 축소(점선임이 드러나는 것이 목적)

마커 SVG는 aria-hidden="true"로 두고 의미는 옆의 한글 텍스트가 전달한다. 범례 전체는 role="list" / role="listitem" 대신 평범한 span 조합으로 두되, 컨테이너에 aria-label="추이 차트 범례"를 주어 스크린리더가 묶음으로 읽게 한다.

배치 — 헤더 라인 우측 그룹에 합류시키되 wrap을 허용한다. 모바일 프레임 폭은 --container-frame: 28rem(448px)이고 Players는 px-4라 내용 폭 ≈ 416px. 좌측 h2("종목별 성장", text-sm bold) ≈ 62px를 빼면 우측에 ≈ 345px가 남고, 범례 3항목(마커 14px + 한글 2자 ≈ 24px + 간격) ≈ 150px + PB : Personal Best ≈ 105px + gap ≈ 30px = ≈ 285px — 한 줄에 들어간다. 그래도 폰트·언어 설정으로 넘칠 수 있으므로 우측 그룹을 flex flex-wrap justify-end gap-x-2 gap-y-1로 두고, 각 항목은 whitespace-nowrap으로 항목 중간에서 끊기지 않게 한다. 넘치면 항목 단위로 우측 정렬 보조 줄에 내려앉으므로 이슈가 금지한 "겹침·어색한 줄바꿈"이 구조적으로 불가능하다. 컨테이너는 items-center → items-start로 바꿔 wrap 시 h2가 세로 가운데로 밀리지 않게 한다.

개별 카드 UI는 손대지 않는다 — GrowthStatCard·TrendChart의 렌더는 무변화, 이번 변경은 섹션 헤더 한 줄과 신규 컴포넌트뿐이다.

4작업 단계

  1. TrendLegend 컴포넌트 신설 — 마커 SVG 3종(본인 stroke-primary+fill-primary / 팀원 stroke-primary-soft / 목표 stroke-good 점선) + 한글 라벨. 항목 배열을 모듈 상수로 두고 map 렌더, 각 항목 whitespace-nowrap. 컨테이너에 aria-label="추이 차트 범례". 차트 스펙 근거(§07)를 주석으로 남긴다. src/components/charts/trend-legend.tsx
  2. charts 배럴에 export 추가↳ 계획의 "알파벳 순서" 표현은 부정확했다 — 배럴은 컴포넌트 그룹별로 export + export type을 묶는 형식이라 TrendChart 블록 바로 뒤에 붙였다. TrendLegend는 props가 없어 타입 export 없음. — 기존 알파벳 순서 유지(RadarChart 다음, TrendChart 앞/뒤 관례에 맞춰). src/components/charts/index.ts
  3. 섹션 헤더에 배치 — Players.tsx:96-99의 헤더 div를 items-center → items-start, h2에 shrink-0, 우측을 <div className="flex flex-wrap items-center justify-end gap-x-2 gap-y-1">로 감싸 <TrendLegend />와 기존 PB : Personal Best span을 나란히 둔다. 카드 확장 여부와 무관한 상시 렌더. src/pages/Players.tsx
  4. 컴포넌트 유닛 테스트 — 3항목 텍스트 렌더, 마커별 색 클래스(stroke-primary/stroke-primary-soft/stroke-good) 일치, 목표 마커의 stroke-dasharray 존재, 마커 SVG의 aria-hidden. src/components/charts/trend-legend.test.tsx
  5. Players 통합 어서션 추가↳ 계획보다 하나 더 — 상시성 검증을 별도 it("카드를 모두 접어도 범례는 남는다")으로 분리했다. 한 케이스에 렌더·색·상시성을 몰아넣으면 실패 시 원인이 흐려진다. 총 2케이스 추가(기존 7 → 9). — 기존 "기본 선택" 케이스와 별도 it로, 섹션 헤더에 범례 3항목이 PB : Personal Best와 함께 렌더되고 카드를 모두 접어도(첫 카드 재탭) 범례는 남는다는 상시성까지 검증. src/pages/Players.test.tsx
  6. 디자인 PRD 정합 — §05 개인 화면 표의 "확장 추이 차트" 행과 §07 차트 스펙 표에 섹션 헤더 범례(#171)를 한 줄로 반영. 색·점선 표기가 실제 토큰과 어긋나지 않게. docs/prd-design.html
  7. 전체 검증↳ 계획의 수동 확인(dev 서버 448px 육안)은 대체 수행했다 — 이 워크트리에 .dev.vars가 없어 라이브 시트 데이터를 띄울 수 없다(#174와 동일 제약). 대신 실제 TrendLegend를 react-dom/server로 SSR하고 빌드 산출 CSS를 물려 헤드리스 Chrome으로 448 / 360 / 320px 폭을 스크린샷했다: 448·360px는 한 줄에 수용, 320px에서만 PB : Personal Best가 항목 경계에서 우측 정렬 보조 줄로 내려간다(겹침·중간 끊김 없음). 임시 하네스 파일은 측정 후 삭제. — npm run test, npm run typecheck, npm run build 그린 확인. —

5리스크

리스크영향완화책
범례가 길어져 모바일 프레임에서 헤더가 두 줄이 된다세로 공간 4px 남짓 증가 — 기능 영향 없음실측상 ≈285px로 416px 안에 들어간다. 넘치더라도 flex-wrap + 항목 whitespace-nowrap이라 항목 단위로만 내려가 겹침·중간 끊김은 발생하지 않는다(이슈의 금지 조건은 충족)
범례 색과 차트 실제 stroke가 시간이 지나며 갈라진다범례가 거짓을 말함범례가 Tailwind 색 클래스를 차트와 동일한 이름으로 쓰고, 두 파일을 같은 charts/ 폴더에 둔다. 테스트가 클래스명을 직접 어서션하므로 한쪽만 바뀌면 실패한다
점선 마커가 14px 폭에서 실선처럼 보인다"목표는 점선" 전달 실패차트의 4 4 대신 3 2로 축소해 14px 안에 최소 3칸을 확보. 축소는 표현 목적이며 차트 자체 대시는 그대로 둔다
"팀원" 표현이 부정확(배경 라인 = 본인 제외 전체 선수)사소한 의미 오차이슈 본문이 지정한 문구를 그대로 쓴다. 실제로도 본인 제외 전 선수이므로 "팀원"이 맞다(buildTrendSeries가 본인을 highlight로 분리)

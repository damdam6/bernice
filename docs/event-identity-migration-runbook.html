#178 종목 ID 이전 실행 지침

#177 스키마 계약 · 기준 main: 4704232 (#182) · 2026-09-29

운영 이전 미완료. 이 PR은 도구·로컬 테스트·절차를 제공한다. 운영 스냅샷/매핑과 실제 Google 수식·데이터 보존·복구 검증은 2026-09-29 비공개 복제본에서 완료했다. 일반 편집자 계정 보호 동작, 배포 앱 E2E, 사용자 승인 및 운영 적용은 아직 남아 있다. #178을 닫지 않는다. 합성 테스트 데이터는 운영 자료가 아니다. seed-sheet.mjs 및 기존 protect-sheet.mjs를 실행하지 않는다.

권한과 사전 준비

  • Node 22 이상, npm ci. GOOGLE_APPLICATION_CREDENTIALS에 서비스 계정 JSON 파일 경로를 설정하거나 비밀 환경변수 GOOGLE_SERVICE_ACCOUNT_KEY를 사용한다. CLI는 .dev.vars를 자동으로 읽지 않는다. 키·토큰을 명령행/PR/로그에 넣지 않는다.
  • 조회/백업은 spreadsheets.readonly 범위와 해당 파일 열람 권한, 적용/복제 검증은 spreadsheets 범위와 파일 및 대상 보호 범위 편집 권한이 필요하다. 보호 범위 편집자로 실제 소유자와 서비스 계정 이메일을 명시한다. 그룹/도메인 전체 편집 권한은 추가하지 않는다.
  • 전체 통합문서를 Google Drive의 '사본 만들기'로 비공개 백업본과 별도 검증본 두 개 복사한다. 공유된 폴더의 상속 권한을 확인한다. 원본·백업·검증본 ID가 서로 다른지 확인하고 기록한다. Sheets 탭별 복사나 XLSX 변환은 전체 파일 백업의 대체가 아니다.
  • Drive 복사 권한은 Sheets 편집 권한과 별도다. 복제본의 보호가 동일하게 복사되었다고 가정하지 말고 원본 스냅샷과 대조한다. JSON에는 입력 원값·수식·평가값·서식·보호를 보관하지만 Drive 파일 ACL, 소유권, 버전 기록은 포함되지 않는다.
  • 모든 산출물 디렉터리는 저장소 밖의 새 비공개 경로여야 한다. 파일 0600/디렉터리 0700으로 만들고 기존 파일을 덮어쓰지 않는다. 별도 암호화 백업 저장소에도 복사하고 접근자를 제한한다. 공개 PR에는 수치 요약과 성공/실패만 올린다.

1. 사전 검사와 기본 dry-run

export GOOGLE_APPLICATION_CREDENTIALS=/secure/bernice-service-account.json
npm run migrate:events -- --sheet SHEET_ID \
  --editors OWNER_EMAIL,SERVICE_ACCOUNT_EMAIL --out /secure/run-178

명시적인 mode가 없으면 읽기 전용이다. 전체 spreadsheets.get(includeGridData=true)를 두 번 조회하여 일치할 때만 백업한다. 이는 완전한 동시 편집 잠금이 아니다. 임시 변동 수식/다른 편집 때문에 차이가 나면 중단하고 쓰기 중지 후 다시 실행한다. 운영 ID 기본값은 없다.

파일검토 내용
before.json전체 탭의 원값·수식·평가값·서식·보호·메타데이터. 매핑 검사가 실패해도 먼저 백업한다.
plan.json / review.json원본 해시, 계획 해시, 모든 종목의 원본 행→현재 앱 ID→이름→회차/열/기존 헤더/수식. 참조가 없는 종목도 포함. 실제 셀 변경 전/후와 추가 보호 목록.
requests.json검토용 Sheets 요청. apply는 이 파일을 실행하지 않고 백업에서 재생성한 계획과 plan.json이 일치하는지 확인한다.

오프라인 입력은 --sheet 대신 --snapshot /secure/snapshot.json을 사용한다. 값만 내보낸 CSV가 아닌 완전한 Sheets 응답이어야 한다. 오프라인 테스트 성공은 실제 Google 평가나 원본 백업을 증명하지 않는다.

미지/중복/빈 이름 헤더, ID 누락·중복, 종료일 모순, 잘못된 참가자, 헤더 없는 점수 열, 수식 오류, 쓰기 대상 병합 셀, 수식으로 계산된 영구 ID는 오류다. 분류되지 않은 추가 탭도 자동 무시하지 않고 중단하므로 별도 검토가 필요하다. 이름 매핑에 날짜/행 순서 추정은 사용하지 않는다. 실패 데이터를 임의 수정하거나 운영 행을 삭제하여 우회하지 않는다.

2. 변경 범위와 원자성

A:F와 선택 H는 그대로 둔다. G1과 유효 종목 행의 G셀에는 앱의 기존 legacy-row-N을 문자열로 저장한다. 중간 빈 행 때문에 생긴 번호 공백도 보존한다. 이미 G가 있으면 현재 고정 ID를 그대로 사용한다. 새 UUID를 발급하지 않는다.

회차 첫 행의 B열 이후만 id:<고정 ID> + CHAR(10) + ID 기반 이름 조회 수식으로 바꾼다. EXACT가 대소문자/와일드카드 ID를 구분한다. 참가자 행, 점수 셀, 기존 열 순서는 변경하지 않는다. G가 물리적으로 없으면 오른쪽 끝에 필요한 열만 추가한다. 기존 열 사이 삽입은 하지 않는다.

G 전체 열과 모든 회차 첫 행에 강제 보호를 추가한다. 기존 보호는 삭제·확대·완화하지 않는다. 신규 보호 ID는 기존 ID와 충돌하지 않게 계획에 확정한다. G/헤더/보호/필요한 열 추가를 하나의 spreadsheets.batchUpdate로 보낸다. 검증 실패 요청은 전체 배치 실패이며 자동 분할하지 않는다. 네트워크 오류/시간 초과 후에는 재전송하지 않고 현재 상태를 조회한다.

재실행 시 동일 ID·동일 수식·동일 보호면 변경 0개다. 최초 계획을 다시 적용하려 하면 원본 해시가 달라 차단된다. 현 상태로 새 dry-run을 만들어 변경 0개를 확인한다.

3. 복제본 실제 검증 — 필수 승인 자료

검증본에 대해 새 dry-run을 만든다. 운영 계획의 ID만 바꿔 재사용하지 않는다. 복제본 변경 계획을 확인하고 아래 apply 명령을 검증본 ID/해시로 실행한다. 2026-09-29 연결된 Drive/Sheets로 비공개 복제본에서 실제 수식 평가, 혼재 헤더, 이름 변경, 동명·다른 ID, 기록 수정, 새 회차 생성, 재실행, 점수 보존 복구를 통과했다. 쓰기·조회는 실제 Sheets I/O와 운영 파서/계산/계획 함수를 사용했으며 배포 앱 전체 E2E와 일반 편집자 계정의 보호 수정 거부는 미검증이다. 아래 표는 재현 절차다.

시나리오실행·판정
기본 이전apply 후 verification.json passed=true. 실제 effectiveValue가 기대한 ID+이름과 같고 오류 없음. 목표·종료일·점수 원값·수식·행/열·참가자·랭킹·달성 여부·추이·최고기록·홈 달성률 전체 비교 통과.
혼재 헤더검증본에서 한 헤더만 원래 이름/참조 수식으로 되돌린 뒤 새 dry-run/apply. ID 매핑과 기존 기록 유지 확인. 중복 ID·미지 이름·모호한 이름으로 바꾸면 쓰기 전에 오류 확인.
이름 변경검증본 목표 A의 이름만 변경. G와 회차 수식 첫 줄 ID는 불변, 실제 Sheets 둘째 줄만 갱신. 캐시 없는 앱 응답에서 모든 역사적 수치와 ID를 비교.
동명·다른 ID검증본에서만 테스트 행에 별도 ID를 부여하고 동명 종목을 준비. ID 헤더는 각각 독립 목표/점수로 연결되고, 모호한 이름 헤더는 거부되는지 확인. 이는 운영 신규 종목 등록(#179/#181)이 아니다.
기록 수정검증본을 바라보는 #182 이후 앱에서 기존 회차 점수 수정. 요청 ID와 물리적 대상 셀 일치 확인. 테스트 수정값/기존값을 비공개 기록.
새 회차검증 앱에서 미사용 날짜 생성. 실제 헤더 수식 평가와 기록 저장·조회 확인. 종료된 종목 제외 확인. 새 회차의 보호 정책도 별도 확인: 이번 CLI는 계획 시 존재한 회차만 보호하며 이후 생성 회차 보호를 자동 변경하지 않는다.
보호의 실제 효력일반 편집자 계정으로 G·헤더 편집 거부, 허용된 소유자/서비스 계정으로 점수 편집 가능 확인. 서비스 계정 단독 readback은 일반 사용자 편집 차단의 증거가 아니다. 기존 보호도 동일하게 작동하는지 확인.
재실행/복구새 dry-run 변경 0개. 이전 이후 점수 수정 후 rollback 계획/apply → 수정 점수 유지 및 원래 헤더·G·추가 보호만 복구. 이름·종목 정의·회차 구조가 바뀐 경우 자동 복구 거부 확인.

검증 보고서에는 원본/복제 ID, 시점, 소스·계획 해시, 수식 readback, 보호 범위 diff, 두 권한 계정의 동작, 각 시나리오 PASS/FAIL, 변경 목록을 포함한다. 운영 apply 승인은 이 자료와 운영 새 dry-run 실제 변경 목록을 사용자에게 제시한 다음 받는다. CLI 확인 플래그 자체는 복제 검증이나 사용자 승인의 증거가 아니다.

4. 쓰기 중지 → 승인된 적용 → 재개

  1. #182 이후 프론트·Functions가 함께 배포되었는지 확인. 구형 클라이언트 탭 새로고침.
  2. 운영 유지보수 창 설정. 앱의 기록 저장/참가자 추가/회차 생성 API 접근을 인프라에서 중지하고, 운영자·수기 편집자·다른 자동화의 편집도 중지. 쓰기 중지 도구를 이 PR이 제공한다고 가정하지 않는다.
  3. 쓰기가 중지된 원본을 다시 백업하고 새 dry-run. 복제 검증 이후 원본이 달라졌다면 변경을 비교하고 영향 부분을 재검증. 정확한 계획 해시로 사용자 승인.
  4. 아래 apply를 실행. 적용 직전 다시 전체 해시 확인. Google Sheets에는 이 읽기와 쓰기 사이를 조건부 CAS로 잠그는 기능을 이 도구가 사용하지 않으므로 운영 쓰기 중지는 필수.
  5. apply-intent.json을 배치 전 저장하고, 적용 후 after.json 및 verification.json을 저장. 성공 메시지까지 확인. 사후 검증 실패 시 쓰기를 재개하지 않는다.
  6. 인증된 앱에서 POST /api/refresh, 이어서 GET /api/records로 같은 colo의 시트 재조회 결과 확인. 임의 쿼리 파라미터로 캐시를 우회할 수 없다. 기존 캐시 삭제는 요청이 도달한 Cloudflare colo에만 적용된다. 다른 colo의 캐시 최대 15분 및 클라이언트 Query 캐시를 고려해 열린 탭 새로고침/재조회를 실시한다.
  7. 운영 조회·수치·보호 확인 후 쓰기 재개. 동명 신규 종목 등록은 모든 과거 이름 헤더의 ID 전환 확인 이후 별도 #179/#181로 진행한다.
npm run migrate:events -- --mode apply --run /secure/run-178 \
  --confirm SHEET_ID --approved-plan REVIEWED_PLAN_HASH --writes-frozen

# 네트워크 오류·검증 실패 시 읽기 전용 재확인 (새 출력 폴더)
npm run migrate:events -- --mode verify --run /secure/run-178 \
  --out /secure/recheck-178

5. 복구

쓰기 중지 유지 → 현재 점수 포함 전체 스냅샷 백업 → 아래 rollback dry-run → 검토/승인 → 동일 apply 흐름. 최초 run 폴더의 before.json과 plan.json이 필요하다. 이전 도구가 바꾼 셀의 현재 수식/ID가 계획과 정확히 일치하고 목표·회차 구조가 유지되는 경우에만 자동 복구한다. 이전 후 점수 수정은 허용하며 점수 셀은 절대 복구 요청에 포함하지 않는다.

npm run migrate:events -- --mode rollback --run /secure/run-178 \
  --out /secure/rollback-178
npm run migrate:events -- --mode apply --run /secure/rollback-178 \
  --confirm SHEET_ID --approved-plan ROLLBACK_PLAN_HASH --writes-frozen

원래 G셀·회차 헤더 입력값/수식을 복원하고 이번 계획이 추가한 보호만 삭제한다. 원래 보호는 그대로 둔다. 추가한 빈 G열의 물리적 열 수는 줄이지 않는다. 수식 평가 오류가 난 이전 헤더도 입력 수식이 계획과 같으면 복구 가능하다. 복구 사후 비교는 해당 헤더에 한해 승인 매핑의 ID로 연결하고 현재 점수/목표를 사용한다.

종목명/목표/ID/회차 구조/관리 보호가 이후 변경됐거나 일부 적용 상태가 예상과 다르면 자동 복구를 거부한다. 운영자가 최신 백업과 변경 이력을 대조하여 별도 복구 계획을 작성한다. 전체 과거 스냅샷을 덮어쓰거나 이전 후 점수를 삭제하지 않는다. 새 코드 유지 상태에서 시트를 먼저 복구·검증하고 캐시 갱신 후 재개한다. ID 헤더 상태에서 구코드만 단독 롤백하지 않는다.

테스트의 스냅샷은 임의 생성한 소규모 합성 데이터다. 전송 시뮬레이터는 Google 수식을 계산하지 않는다. 2026-09-29 Drive 연결 이후 운영 전체 스냅샷·매핑 및 비공개 백업/검증본 생성, 실제 Google 평가/보존/복구 검증을 완료했다. 검증용 점수·종목·회차는 정리했고 검증본은 ID 이전 완료 상태로 보관했다. 마지막 운영 readback은 최초 스냅샷과 동일했다. 복사본은 소유자만 접근하며 Google이 공유되지 않은 서비스 계정을 보호 편집자에서 제외하므로 복제본에서는 소유자 정책으로, 운영 계획에서는 기존 소유자+서비스 계정 정책으로 작성했다. 원본 보호 정책 전체는 비공개 스냅샷에 별도 보관했다. 일반 편집자 계정의 실제 보호 거부 및 서비스 계정 인증 쓰기, 배포 앱 E2E/캐시·쓰기 중지/재개는 미검증이다. 실제 참가자·점수·시트 ID·백업/계획은 공개 저장소에 저장하지 않는다. 운영 쓰기는 명시적 승인 전 실행하지 않는다.
